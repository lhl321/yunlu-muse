# 云麓AI 实战教程

> 云麓AI 不是简单的自动化工具，是 **AI 智能体的工作流执行引擎**。
> 你可以在画布上拖节点建流程，也可以让智能体通过 MCP 帮你创建、优化、排错工作流。
> 本教程围绕场景展开，基础操作带过，重点讲 AI 怎么用、工作流怎么建。

---

## 这个系统是什么

```
你描述需求
   ↓
智能体通过 MCP 创建工作流（或你自己在画布上建）
   ↓
工作流执行：触发器 → AI节点 → 逻辑判断 → 输出动作
   ↓
结果推送到微信、设备、文件、笔记
```

| 概念 | 说明 |
|------|------|
| 工作流 | 一条自动化流程，由节点和连线组成 |
| 节点 | 流程中的一个步骤（触发、AI、判断、动作等） |
| AI节点 | 调用大模型的节点（生成、判断、选择） |
| MCP | 外部智能体接入协议，让豆包/workbuddy/CodeBuddy能操作工作流 |
| 脚本节点 | 执行Python代码，扩展能力 |
| 子工作流 | 工作流里调用另一个工作流，复用逻辑 |

## 入门篇

### 第1章：5分钟做第一个工作流

**目标**：建一个"每天早上8点播报天气"的工作流。

1. 左侧「工作流」→ 点「＋ 新建工作流」
2. 画布上拖入「定时触发」节点，设置每天8:00
3. 拖入「HTTP请求」节点，调用天气API
4. 拖入「AI生成」节点，让AI把天气数据整理成自然语言
5. 拖入「微信推送」节点，把结果发给自己
6. 连线：定时触发 → HTTP请求 → AI生成 → 微信推送
7. 点「保存并启用」
8. 点「试跑」测试一次

**核心概念**：
- 从左到右执行，连线决定顺序
- 每个节点的输出可以被后面的节点引用
- AI节点可以把原始数据变成人话

---

### 第2章：看懂画布（快速带过）

**节点分类**（左侧节点库）：
- 触发器：定时、手动、webhook、设备状态
- AI能力：AI生成、AI判断、AI多条件判断、AI选择分支
- 逻辑控制：多条件判断、延时、循环
- 输出动作：HTTP请求、微信推送、设备控制、文件写入
- 数据处理：数据提取、字段映射、变量设置
- 记忆系统：读写记忆、知识库检索
- 第三方：海康、小米、HomeAssistant、笔记集成
- 实验功能：脚本执行、项目调用

**端口颜色**（按数据类型）：
- 紫色：输入/文本
- 蓝色：输出
- 粉色：图片
- 橙色：文件
- 青色：语音/结构化数据
- 绿色：条件成立/触发
- 红色：条件不成立/异常

**变量引用**：
- 上一个节点的输出用 `{{节点ID.字段名}}` 引用
- 比如 `{{node_abc.data.temperature}}`

---

### 第3章：调试三板斧

**第一板：试跑**
- 点右上角「试跑」，工作流跑一遍
- 每个节点显示：成功/失败、耗时、输入输出
- 点节点看详细日志

**第二板：节点级调试**
- 右键节点 →「测试此节点」
- 只跑这一个节点，手动填输入
- 看输出是否符合预期

**第三板：日志查看**
- 左侧「运行记录」→ 点某次运行
- 看每个节点的输入输出和报错
- AI节点的报错通常是：模型调用失败、提示词太长、输出格式不对

**常见报错**：
- `Read timed out`：HTTP请求超时，调大超时时间或加重试
- `字段不存在`：变量引用写错了，检查节点ID和字段名
- `AI生成失败`：模型没配好，去「模型管理」检查
- `连接失败`：目标服务不可达，检查URL和网络

## AI智能体与工作流篇

### 第4章：主站MCP接入

**什么是主站MCP**：
- 外部智能体（豆包、workbuddy、CodeBuddy）通过MCP协议连接到云麓AI
- 可以列出、创建、修改、触发工作流
- 可以管理脚本、查看运行记录
- 你对智能体说"帮我建一个每天播报天气的工作流"，它自动帮你建好

**MCP工具列表**：

| 工具 | 权限 | 作用 |
|------|------|------|
| `brain_list_workflows` | 读 | 列出允许AI访问的工作流 |
| `brain_get_workflow` | 读 | 看一个工作流的图结构 |
| `brain_get_node_catalog` | 读 | 列出现有节点类型 |
| `brain_get_node_detail` | 读 | 看某个节点要配哪些字段 |
| `brain_validate_workflow` | 读 | 校验工作流是否正确（不落库） |
| `brain_list_executions` | 读 | 查运行记录 |
| `brain_get_execution` | 读 | 看某次运行每个节点的结果 |
| `brain_list_scripts` | 读 | 列出脚本 |
| `brain_get_script` | 读 | 读脚本内容 |
| `brain_create_workflow` | 写 | 新建工作流（默认停用） |
| `brain_update_workflow` | 写 | 修改工作流（带乐观锁） |
| `brain_toggle_workflow` | 写 | 启用/停用 |
| `brain_trigger_workflow` | 写 | 真跑一次，拿回运行号 |
| `brain_create_script` | 写 | 新建脚本 |
| `brain_update_script` | 写 | 修改脚本 |
| `brain_run_script_trial` | 写 | 试跑脚本 |

**接入流程**：
1. 后台管理 → MCP接入 → 新建密钥（`bt_` 开头）
2. 复制配置JSON（URL + 密钥）
3. 在豆包/workbuddy/CodeBuddy里添加MCP服务
4. 配置系统提示词（参考第5章）
5. 对智能体说"列出我的工作流"测试连通性

**写入权限控制**：
- 密钥分只读和读写
- 工作流可以单独设置「允许AI访问」
- 新建的工作流默认停用，需要你手动启用
- 修改工作流带乐观锁，防止覆盖你的改动

### 第5章：让智能体帮你建工作流

**提示词怎么写**：

差的提示词：
> 帮我做个工作流

好的提示词：
> 帮我建一个工作流：每天早上8点触发，调用天气API获取杭州天气，用AI生成一段自然语言的天气播报，通过微信推送给我。天气API地址是xxx，返回JSON格式。

**提示词要点**：
1. **触发条件**：什么时候跑（定时、手动、webhook）
2. **数据来源**：从哪获取数据（API、设备、知识库）
3. **AI处理**：AI要做什么（生成、判断、分类）
4. **输出动作**：结果发到哪（微信、文件、设备）
5. **具体参数**：API地址、城市、接收人等

**智能体建工作流的过程**：
1. 调用 `brain_get_node_catalog` 看有哪些节点可用
2. 调用 `brain_get_node_detail` 看需要的节点怎么配
3. 调用 `brain_create_workflow` 创建工作流（默认停用）
4. 调用 `brain_validate_workflow` 校验是否正确
5. 告诉你"建好了，去试跑一下，没问题再启用"
6. 你试跑确认后，调用 `brain_toggle_workflow` 启用

**系统提示词模板**（配在智能体全局）：
```
你是云麓AI工作流助手，通过MCP操作工作流。

## 工作流程
1. 建工作流前，先 brain_get_node_catalog 看有哪些节点
2. 不确定的节点，先 brain_get_node_detail 看配置项
3. 创建后必须 brain_validate_workflow 校验
4. 新建的工作流默认停用，让用户试跑确认后再启用
5. 修改工作流要带乐观锁，防止覆盖用户改动

## 重要规则
- 只能使用MCP工具，禁止凭记忆编节点类型
- 建之前先问清楚：触发条件、数据来源、AI处理、输出动作
- 不要直接启用，让用户试跑确认
- 报错时先 brain_get_execution 看日志，再判断怎么改
```

### 第6章：让智能体帮你优化和排错

**优化工作流**：
- 你说："这个工作流跑得太慢了，帮我优化一下"
- 智能体调用 `brain_get_workflow` 看结构
- 调用 `brain_list_executions` 看历史运行耗时
- 找出瓶颈节点，提出优化建议
- 你确认后，调用 `brain_update_workflow` 修改

**排错工作流**：
- 你说："这个工作流失败了，帮我看看"
- 智能体调用 `brain_get_execution` 看最新一次运行的日志
- 定位失败节点和报错原因
- 调用 `brain_get_node_detail` 看配置是否正确
- 给出修复方案，你确认后修改
- 修改后调用 `brain_trigger_workflow` 试跑验证

**常见排错场景**：

| 问题 | 智能体怎么查 | 怎么修 |
|------|------------|--------|
| AI节点输出格式不对 | 看AI节点的输入输出 | 调整提示词，加格式约束 |
| HTTP请求超时 | 看HTTP节点的耗时和报错 | 调大超时、加重试、换API |
| 变量引用错误 | 看节点的输入配置 | 修正 `{{节点ID.字段}}` |
| 条件判断不生效 | 看判断节点的输入和条件 | 检查字段名和比较符 |
| 工作流跑一半停了 | 看运行记录哪个节点失败 | 定位失败节点，逐个排查 |

**智能体排错的优势**：
- 不用你自己翻日志
- AI能理解报错信息，给出可执行的修复方案
- 可以直接修改工作流并试跑验证
- 排错过程会记录在对话里，下次遇到类似问题直接复用

## AI节点场景化篇

### 第7章：AI生成节点场景

**AI生成节点能做什么**：
- 把原始数据变成自然语言
- 生成文案、摘要、标题
- 翻译、润色、改写
- 结构化数据转文本

**场景1：天气播报**
- 前置：HTTP请求获取天气JSON
- AI提示词：`把下面的天气数据整理成一段自然语言的早间播报，包括温度、天气、穿衣建议：{{http_node.data}}`
- 输出：一段人话的天气播报
- 后置：微信推送

**场景2：日报生成**
- 前置：从知识库/记忆里读取今天的事件
- AI提示词：`根据以下内容生成一份工作日报，分"完成事项"、"进行中"、"明日计划"三部分：{{data}}`
- 输出：结构化的日报
- 后置：写入笔记/发送邮件

**场景3：消息内容生成**
- 前置：传感器数据（温度、湿度、空气质量）
- AI提示词：`根据以下室内环境数据，生成一条温馨提示，如果有异常要提醒：{{sensor_data}}`
- 输出：温馨提示或预警
- 后置：微信推送/语音播报

**AI生成节点的提示词技巧**：
- 明确输出格式："用JSON输出"、"分三点"、"不超过100字"
- 给上下文："你是一个天气播报员"、"你是一个专业的秘书"
- 引用变量：用 `{{节点ID.字段}}` 把前置节点的输出传进去
- 失败兜底：AI生成失败时，用默认文本代替

---

### 第8章：AI判断节点场景

**AI判断节点能做什么**：
- 内容分类（正面/负面、紧急/普通）
- 情绪分析（开心/生气/焦虑）
- 意图识别（查询/投诉/建议）
- 是/否判断（是否包含关键词、是否符合规则）

**场景1：消息分类处理**
- 前置：收到一条消息（微信/webhook）
- AI判断：`判断这条消息是"工作"、"生活"还是"垃圾"，只输出一个词：{{message}}`
- 输出：分类结果
- 后置：多条件判断 → 工作消息发工作群、生活消息发个人、垃圾消息丢弃

**场景2：紧急事件识别**
- 前置：传感器报警（烟雾、漏水、入侵）
- AI判断：`根据以下传感器数据，判断是否为紧急事件，输出"紧急"或"普通"：{{sensor_data}}`
- 输出：紧急/普通
- 后置：紧急 → 打电话+微信+声光报警；普通 → 只发微信

**场景3：内容审核**
- 前置：用户提交的内容
- AI判断：`判断以下内容是否包含违规信息，输出"通过"或"拒绝"：{{content}}`
- 输出：通过/拒绝
- 后置：通过 → 发布；拒绝 → 返回提示

**AI判断节点的用法**：
- 提示词要求输出固定的几个词（如"紧急/普通"）
- 后面接「多条件判断」节点，根据AI的输出走不同分支
- 判断失败时默认走哪个分支要配置好

---

### 第9章：AI多条件判断场景

**AI多条件判断和普通多条件判断的区别**：
- 普通多条件：用规则匹配（字段A > 10 且 字段B = "xxx"）
- AI多条件：用AI理解语义后判断（"这条消息看起来像不像投诉"）

**场景：复杂工单路由**
- 前置：收到一条用户反馈
- AI多条件判断：
  - 条件1：`是否包含"退款"或"退货"？` → 走售后流程
  - 条件2：`是否包含"不会用"或"怎么操作"？` → 走客服流程
  - 条件3：`是否包含"建议"或"希望"？` → 走产品建议
  - 都不满足 → 走通用工单
- 每个条件可以配独立的AI提示词
- 满足哪个条件走哪个分支

**什么时候用AI多条件**：
- 规则写不清楚的时候（语义理解）
- 条件太多，普通判断写不下的时候
- 需要模糊匹配的时候（"大概是这个意思"）

**什么时候不用**：
- 精确匹配（状态码=200、温度>30）→ 用普通多条件
- 性能要求高 → AI判断有延迟，能不用就不用

---

### 第10章：AI选择分支场景

**AI选择分支能做什么**：
- 根据内容动态选择下一步执行哪个分支
- 和AI判断类似，但可以选多个选项中的一个
- 适合：智能分发、动态路由

**场景：智能回复**
- 前置：收到用户消息
- AI选择分支：
  - 选项A："用户在问产品信息" → 调用产品知识库回复
  - 选项B："用户在投诉" → 转人工
  - 选项C："用户在闲聊" → 自动回复寒暄
  - 选项D："用户在提建议" → 记录到建议库
- AI根据消息内容选择一个选项
- 走对应的分支处理

**AI选择和AI判断的区别**：
- AI判断：是/否，满足条件走A，不满足走B
- AI选择：多个选项，选其中一个走

---

### 第11章：AI节点通用技巧

**提示词模板库**：

| 用途 | 提示词模板 |
|------|-----------|
| 摘要 | `把以下内容总结成3句话：{{content}}` |
| 分类 | `把以下内容分类为"工作/生活/其他"，只输出一个词：{{content}}` |
| 翻译 | `把以下内容翻译成英文：{{content}}` |
| 提取 | `从以下内容中提取日期、地点、人物，用JSON输出：{{content}}` |
| 判断 | `判断以下内容是否为紧急事件，输出"是"或"否"：{{content}}` |
| 生成 | `根据以下数据生成一段温馨提示：{{data}}` |

**变量引用注意事项**：
- 变量用 `{{节点ID.字段名}}`
- 节点ID在节点配置里可以看到
- 字段名要看前置节点的输出结构
- 不确定字段名时，先试跑前置节点，看输出

**AI节点失败处理**：
- AI调用失败时，工作流会报错停止
- 可以在AI节点后面加「多条件判断」，判断输出是否为空
- 为空时走兜底分支（用默认文本、发通知等）
- 重要的工作流建议加错误处理（参考第18章）

**成本控制**：
- AI节点每次执行都消耗模型额度
- 能用普通判断就不用AI判断
- 长文本先摘要再传给AI，减少token消耗
- 批量处理时，考虑用一次AI调用处理多条，而不是每条调一次

## 工作流实战场景篇

### 第12章：智能家居自动化场景

**场景1：早上智能唤醒（含AI）**
- 触发：每天7:30定时
- 步骤1：HTTP请求获取天气和路况
- 步骤2：AI生成 → 把天气、路况、日程整合成一段自然语言的晨间播报
- 步骤3：AI判断 → 今天是否下雨？下雨就提醒带伞
- 步骤4：设备控制 → 打开窗帘、打开咖啡机
- 步骤5：语音播报 → 播放AI生成的晨间播报

**场景2：离家安防（含AI）**
- 触发：手机离开家（地理围栏）
- 步骤1：设备控制 → 关闭所有灯、空调
- 步骤2：延时2分钟
- 步骤3：AI判断 → 检查门窗传感器状态，是否有未关闭的？
- 步骤4：如果有未关闭 → 微信提醒"窗户没关"
- 步骤5：启用安防模式

**场景3：异常预警（含AI）**
- 触发：烟雾/漏水/燃气传感器报警
- 步骤1：AI判断 → 根据传感器数据判断严重程度（紧急/普通）
- 步骤2：紧急 → 打电话+微信+声光报警+关闭阀门
- 步骤3：普通 → 微信提醒+推送现场截图

**场景4：回家模式（含AI）**
- 触发：手机到家（地理围栏）
- 步骤1：设备控制 → 开灯、开空调、开热水器
- 步骤2：AI生成 → 根据今天的天气和时间，生成一句欢迎语
- 步骤3：语音播报 → 播放欢迎语

---

### 第13章：消息通知与推送场景

**场景1：每日摘要推送（含AI）**
- 触发：每天22:00定时
- 步骤1：从记忆/知识库读取今天的事件
- 步骤2：AI生成 → 整理成"今日摘要"，分"完成"、"未完成"、"明日提醒"
- 步骤3：微信推送 → 发给自己

**场景2：监控告警智能分发（含AI）**

## 脚本扩展篇

### 第16章：脚本节点入门

**什么是脚本节点**：
- 执行Python代码
- 可以做AI节点做不了的事（复杂计算、文件处理、调用特殊库）
- 在「实验功能」分类里

**脚本节点能做什么**：
- 复杂数据处理（正则、加密、编码转换）
- 调用Python库（requests、pandas、PIL等）
- 文件读写、压缩、格式转换
- AI节点和HTTP节点搞不定的事

**脚本和AI配合**：
- AI生成代码 → 脚本节点执行
- 脚本处理原始数据 → AI生成自然语言
- AI判断结果 → 脚本执行复杂逻辑

**简单示例**：
```python
# 输入：data = {"name": "张三", "age": 25}
# 输出：格式化后的字符串
name = data.get("name", "")
age = data.get("age", 0)
result = f"{name}今年{age}岁"
return {"result": result}
```

### 第18章：脚本调试与安全

**脚本调试**：
- 右键脚本节点 →「测试脚本」
- 手动填输入，看输出
- print的内容会出现在日志里
- 报错会显示完整traceback

**脚本安全**：
- 脚本在沙箱里执行，不能访问宿主机
- 有超时限制（默认30秒）
- 不能执行危险操作（删除系统文件等）
- 第三方库需要在镜像里预装

**脚本和AI配合的最佳实践**：
- 能用AI做的不用脚本（AI更灵活）
- 能用脚本做的不用AI（脚本更快更便宜）
- AI负责理解和生成，脚本负责计算和处理
- 复杂流程：AI判断 → 脚本执行 → AI总结

## 进阶篇

### 第19章：子工作流（项目调用）

**什么是子工作流**：
- 工作流里调用另一个工作流
- 复用逻辑，不用重复建
- 比如："发通知"子工作流，所有工作流都可以调用

**怎么用**：
- 拖入「项目调用」节点
- 选择要调用的工作流
- 传入参数
- 等待子工作流完成，拿回输出

**注意事项**：
- 子工作流有超时时间（默认300秒）
- 子工作流失败，父工作流也会失败
- 可以并行调用多个子工作流

---

### 第20章：错误处理与兜底

**为什么需要错误处理**：
- HTTP请求可能超时
- AI调用可能失败
- 设备可能不在线
- 没有错误处理，工作流一错就停

**错误处理方式**：
1. **节点级重试**：HTTP请求节点可以配置重试次数
2. **条件判断兜底**：AI生成后判断输出是否为空，为空走默认
3. **失败分支**：很多节点有 `fail` 输出端口，接失败处理
4. **全局兜底**：重要工作流加一个"失败通知"分支

**示例：AI生成失败兜底**
- AI生成节点 → 多条件判断 → 输出是否为空？
- 不为空 → 正常推送
- 为空 → 用默认文本"今日数据获取失败"推送 + 通知管理员

---

### 第21章：性能优化

**优化方向**：
1. **并行执行**：没有依赖关系的节点并行跑（比如同时调3个API）
2. **减少AI调用**：能用普通判断就不用AI，能一次处理就不多次
3. **缓存结果**：不常变的数据（天气、配置）可以缓存
4. **超时设置**：合理设置超时，不要等太久
5. **子工作流复用**：重复逻辑抽成子工作流，减少节点数

**性能监控**：
- 运行记录里看每个节点的耗时
- 找出最慢的节点，针对性优化
- AI节点通常是最慢的，考虑是否能简化提示词
