# MuseNote 实战教程

> MuseNote 不是笔记软件，是 **AI 智能体工作空间**。
> 笔记是工作台，任务是指令，智能体是执行者，结果回写到笔记。
> 本教程围绕这个核心展开，笔记的基础排版功能只带过。

---

## 这个系统是什么

```
你在笔记里写下任务
       ↓
智能体接单，执行工作
       ↓
结果写回笔记
```

| 概念 | 传统笔记软件 | MuseNote |
|------|------------|----------|
| 笔记 | 文档，存文字 | 工作台，智能体在这里工作 |
| 任务块 | 待办清单 | 给智能体的指令 |
| AI助手 | 聊天机器人 | 轻量快捷操作（选中文字处理） |
| 智能体 | 无 | 任务执行者，自动读写笔记 |
| AI存储 | 无 | 智能体的文件系统和技能库 |
| MCP | 无 | 外部智能体接入标准协议 |
| 联邦 | 无 | 跨工作空间共享协作 |

理解了这个定位，后面的内容就顺了。

---

## 快速开始：5分钟体验核心价值

**前提**：已在「设置 → 智能体管理」绑定至少一个智能体（参考第3章）。

1. 新建一篇笔记，标题写「我的第一个智能体任务」
2. 在笔记里插入一个**任务块**（工具栏 → 块 → 待办任务）
3. 任务内容写：「帮我把这篇笔记整理成三条要点，新建一篇总结」
4. 点编辑器顶部 **AI 助手**按钮（云小麓图标）
5. 顶部下拉从「大模型」切到「智能体」，选择你的智能体
6. 点发送
7. 看智能体接单 → 执行 → 结果回写到笔记

这就是 MuseNote 的核心运转方式。后面的章节是细节。

## 第一篇：工作空间基础

### 第1章：界面与笔记基础

**学习目标**：熟悉界面，知道在哪写任务、在哪看结果。

**三栏布局**：

| 区域 | 作用 |
|------|------|
| 侧边栏（最左） | 导航、笔记本、AI存储、共享、用户菜单 |
| 笔记列表（中间） | 当前分类下的笔记卡片 |
| 编辑器（最右） | 笔记内容，智能体在这里工作 |

**侧边栏导航**（从上到下）：
- **星标**：标记重要的笔记
- **任务**：跨所有笔记汇总的未完成任务（智能体的任务也在这里）
- **AI 存储**：智能体的文件系统（技能、工作目录、笔记附件）
- **回收站**：已删除的笔记
- **共享**：我的共享 / 他人共享
- **笔记本列表**：笔记的分类

**通知铃铛**（右上角）：
- 智能体任务完成、共享邀请、审核请求、系统通知都会在这里提醒
- 点铃铛查看通知列表，点某条通知跳转到对应内容
- 可单条标记已读，也可一键全部已读
- 通知类型：任务完成、共享邀请、修改待审、系统公告

**编辑器顶部按钮**（从左到右）：

| 按钮 | 作用 |
|------|------|
| AI助手 | 打开AI面板，派任务或快捷操作 |
| 历史记录 | 查看笔记变更，恢复旧版本 |
| AI阅读 | 开关：关闭后智能体看不到这篇笔记 |
| MCP编辑 | 开关：允许外部智能体修改这篇 |
| 隐私 | 加密笔记，打开需密码 |
| 锁定 | 锁定编辑，防止误改 |
| 星标 / 置顶 / 删除 | 常规操作 |

**新建笔记**：
- 中间列表顶部「＋ 新建」
- 或在笔记本上右键 → 新建笔记
- 新建的笔记默认开启「AI阅读」和「允许MCP编辑」

**笔记基础排版**（只列常用，不展开）：
- 工具栏：段落样式、字体字号、加粗斜体、颜色、列表、对齐
- 插入：引用、分割线、表格、思维导图、图片、附件、链接
- 块：任务块（重点，下一章）、密码块
- 自动保存，底部状态栏显示状态

**快捷键**：

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+B/I/U` | 加粗/斜体/下划线 |
| `Ctrl+Z/Y` | 撤销/重做 |
| `Ctrl+N` | 新建笔记 |
| `Tab/Shift+Tab` | 列表缩进/提升 |

### 第2章：任务块——给智能体的指令

**学习目标**：理解任务块不是待办清单，是给智能体的指令。

**什么是任务块**：
- 工具栏 → 块 → 待办任务，插入一个任务块
- 任务块 = 一条给智能体的指令
- 智能体读取任务内容，执行后回写结果
- 任务块支持子任务嵌套

**任务块结构**：
```
┌─────────────────────────────────┐
│ ☑ 任务标题（第一行，写指令内容）  │
│   开始时间：2026-10-04 14:30    │
│   └─ 子任务1                    │
│   └─ 子任务2                    │
└─────────────────────────────────┘
```

**写好任务指令**：
- 差的指令：「帮我弄一下」
- 好的指令：「搜索最近一周的会议记录，整理出三条待办事项，追加到这篇笔记末尾」
- 明确：做什么、用什么数据、输出到哪里

**任务操作**：
- **完成**：点复选框，背景变浅绿色（智能体完成后自动标记）
- **子任务**：任务内回车新建子任务，或拖拽一个任务到另一个任务内
- **子任务未完成时，主任务不能标记完成**（会提示）
- **完成记录**：右键任务 → 查看完成记录（保留最近10条）
- **调整宽度**：拖拽块右侧边缘

**全局任务视图**：
- 左侧导航点「任务」
- 跨所有笔记汇总未完成任务
- 显示任务标题、所属笔记、截止时间
- 点击直接跳转到对应笔记
- 智能体创建的任务也在这里

**任务和智能体的关系**：
- 你在笔记里写任务块
- 通过AI助手派给智能体
- 智能体执行后回写结果到笔记
- 任务块标记完成
- 这就是完整的闭环

## 第二篇：智能体

### 第3章：绑定智能体

**学习目标**：绑定智能体，让AI自动执行任务并回写笔记。这是系统的核心功能。

#### 3.0 两种智能体怎么选

| 你的需求 | 选哪种 | 原因 |
|---------|--------|------|
| 需要执行命令、跑脚本、操作文件 | 本地智能体（CodeBuddy） | SSH连接，能执行shell命令 |
| 日常问答、内容创作、整理笔记 | 通用智能体（豆包/workbuddy） | MCP连接，云端运行，开箱即用 |
| 两个都要 | 都绑，派任务时选 | 各自独立，互不影响 |

**快速判断**：
- 要它"做事情"（跑脚本、调API、操作文件）→ 本地
- 要它"想事情"（写文案、整理资料、回答问题）→ 通用
- 不确定 → 先绑通用（配置简单），需要时再加本地

---

#### 3.1 本地智能体（CodeBuddy）

**什么是CodeBuddy智能体**：
- 运行在你内网容器里的AI助手
- 通过SSH连接，能执行命令、读写文件、调用MCP工具
- 绑定后可以在笔记里给它派任务，它自动完成并回写结果

**完整绑定流程（六步）**：

**第一步：新建智能体**
1. 左下角点用户头像 → 个人设置 → 智能体管理
2. 点「＋ 新建智能体」
3. 进入配置向导

**第二步：填写SSH连接信息**
- 智能体名称：自定义，如「我的CodeBuddy」
- 类型：codebuddy
- SSH地址：智能体所在服务器的IP或域名
- SSH端口：默认2221
- SSH用户名：如 codebuddy
- SSH密码：对应密码
- 点「测试连接」验证连通性

**第三步：扫码登录**
1. 连接成功后，系统通过SSH执行 `codebuddy login`
2. 弹出登录URL（如 `https://copilot.tencent.com/login?platform=CLI&state=xxx`）
3. 在浏览器中打开该URL，完成扫码或账号登录
4. 页面显示授权成功后，回到向导点「我已完成登录」
5. 系统检测登录状态，成功后进入下一步

**第四步：配置MCP**
1. 系统自动在CodeBuddy中添加MCP服务（名字固定，不可改）
2. MCP地址默认从当前访问地址自动获取
3. 自动创建读写密钥（如已存在则复用）
4. 如果已有同名MCP，提示「覆盖」或「保留」
5. MCP配置完成后，智能体可以访问你的笔记

**第五步：选择模型**
1. 点「刷新模型列表」从CodeBuddy拉取可用模型
2. 列表显示模型名和积分倍率（如 Hy4 preview x0.29）
3. 选择默认使用的模型
4. 积分倍率是动态的，以刷新时为准

**第六步：编辑系统提示词**
- 系统提示词告诉智能体怎么工作
- 默认提示词包含：工作流程、MCP工具说明、重要规则
- 用户可自定义编辑
- 提示词要点：
  - 完成任务后必须写回笔记
  - 二进制文件用上传通道，不要用write_file
  - 标记任务完成时comment必填
  - 有未完成子任务时主任务不能完成

**智能体管理页面**：

每个智能体显示为一张卡片：
- 名称 + 编号
- 状态标签：就绪（绿）/ 已连接（蓝）/ 未连接（灰）/ 错误（红）
- SSH地址：username@host:port
- MCP状态：已配置 / 未配置
- 默认模型

卡片操作按钮：
- ⚡ 测试连接
- 🔌 MCP状态
- 🧠 模型列表（刷新、切换默认）
- 📝 全局提示词（编辑）
- ✏️ 编辑
- 🗑️ 删除

**在云小麓对话框里使用智能体**：

绑定智能体后，在笔记编辑器顶部点AI助手按钮（云小麓图标）打开对话框。

**切换到智能体模式**：
- 对话框顶部下拉，从「大模型」切换到「智能体」
- 选择要使用的智能体
- 切换后历史话题独立保存，和大模型对话不混

**两种执行模式**：

| 模式 | 按钮 | 适用场景 | 特点 |
|------|------|---------|------|
| 对话模式 | 💬 新对话 | 问答、讨论、轻量处理 | 实时显示输出，边说边看 |
| 任务模式 | 📌 新任务 | 复杂任务、长时间执行 | 静默执行，结果自动写回笔记 |

**对话模式**：
- 正常聊天，实时显示智能体的输出
- 适合：问答、讨论、简单的文字处理
- 输出可以复制、插入笔记
- 历史话题保存在服务端，换浏览器也能看到

**任务模式**：
- 发送后静默执行，对话框里只留一个任务块
- 任务块显示：
  - 状态：排队中 → 执行中 → 已完成 / 失败 / 已停止
  - 输入内容（你发的任务描述）
  - 输出（可展开/收起）
  - 停止按钮（执行中可点）
- 执行报告会自动写入笔记本
- 生成的文件会存入AI存储空间
- **关闭窗口不停止任务**，后台继续运行，重新打开可恢复状态
- 切模式即开新话题

**怎么选模式**：
- "帮我翻译这段话" → 对话模式（实时看结果）
- "帮我搜索所有笔记，整理出一份年度总结" → 任务模式（长时间执行，结果写回笔记）
- "这段代码有什么问题" → 对话模式
- "帮我写一个部署脚本，存到技能目录" → 任务模式

**注意事项**：
- 同一时间只有一个SSH连接，其他操作排队
- MCP密钥和名字固定绑定，不要手动在CodeBuddy里删除
- 删除智能体不会删除已写入的笔记
- 支持绑定多个智能体，各自独立
- 任务模式下暂不支持图片引用

##### 3.1.1 本地智能体排错

| 问题 | 原因 | 解决 |
|------|------|------|
| 连接失败 | SSH地址/端口/密码错 | 智能体管理 → 测试连接，核对信息 |
| 登录URL不弹出 | CodeBuddy未安装或路径不对 | SSH上去手动执行 `codebuddy login` 看报错 |
| MCP配置失败 | 密钥创建失败或地址不对 | 检查MuseNote的MCP接入页面，密钥是否存在 |
| 任务执行没反应 | 模型没选或积分不足 | 智能体管理 → 模型列表，刷新并选默认模型 |
| 执行一半停了 | 超时或SSH断开 | 任务模式后台执行，重新打开窗口看状态 |
| 输出乱码 | 编码问题 | 检查系统提示词，指定输出编码 |

#### 3.2 通用智能体（豆包 / workbuddy）

**什么是通用智能体**：
- 豆包、workbuddy等云端AI助手
- 它们通过MCP协议连接到你的MuseNote
- 连接后可以搜索、读取、创建、修改你的笔记
- 你对它们说"用我的AI空间..."，它们就会调用MCP工具

**完整接入流程（五步）**：

**第一步：在MuseNote创建MCP密钥**
1. 左下角点用户头像 → 个人设置 → MCP接入
2. 点「＋ 新建密钥」
3. 选择权限：
   - **只读**：只能检索、读取笔记
   - **读写**：可以新建和修改笔记（还需目标笔记打开「允许MCP编辑」）
4. 密钥以 `mn_` 开头，创建后明文留存
5. 一把密钥对一个客户端，不用了随时撤销

**第二步：获取MCP配置**
- 在「MCP接入」页面展开「外部智能体怎么接入」
- 系统自动生成配置JSON，包含：
  - URL：`http://你的域名:8765/mcp`
  - Header：`Authorization: Bearer mn_你的密钥`
- 地址按当前访问方式自动生成，不用手动填
- 点「复制配置」拿到完整JSON

**第三步：在豆包/workbuddy里配置MCP**
1. 打开豆包（或workbuddy）的设置 → MCP / 插件
2. 选择「添加MCP服务」或「自定义MCP」
3. 粘贴上一步复制的JSON配置
4. 保存，重启客户端
5. 连接成功后，MCP工具列表会显示 musenote 的工具

**第四步：给智能体取名和配置提示词**
- 在豆包里给这个MCP连接取名，比如「我的AI空间」
- 配置系统提示词（参考下方模板），告诉它怎么用MCP工具
- **重要**：提示词要配在**全局设置**里，不是单个对话里，否则新对话又忘了

**第五步：使用**
- 对豆包说：「用我的AI空间搜一下最近的会议记录」
- 它会调用 `search_notes` 搜索你的笔记
- 说：「帮我整理这篇笔记的要点，写回笔记里」
- 它会调用 `get_note` 读取 → 整理 → `append_note` 写回

##### 3.2.1 执行任务

**两种触发场景**：

| 触发方式 | 适用场景 | 怎么用 |
|---------|---------|--------|
| 主动触发 | 临时任务、即时需求 | 对豆包说"帮我做XX" |
| 定时触发 | 每日汇总、定期整理 | 用豆包的定时任务/日程功能，定时来扫任务 |

**主动触发**：
- 你对豆包说："帮我查一下最近一周的会议记录，整理出三条待办，追加到《工作笔记》末尾"
- 智能体通过MCP调用 `search_notes` → `get_note` → `append_note`
- 完成后结果已经在笔记里，不用复制粘贴

**定时触发**：
- 利用豆包/workbuddy的定时任务或日程提醒功能
- 设置每天早上9点："去我的AI空间看看有没有未完成任务，帮我处理"
- 智能体定时调用 `list_open_tasks` 扫描任务
- 自动执行后回写结果

**任务来源**：
- 笔记里的任务块（第2章）
- 全局任务列表（`list_open_tasks` 跨所有笔记汇总）
- 你直接在对话里描述的任务

**回写机制**：
- 执行结果写回笔记（`append_note` 或 `create_note`）
- 如果任务来自任务列表，用 `complete_task` 标记完成（comment必填，说明完成情况）
- 有未完成子任务时，主任务不能标记完成（服务端会拒绝）

##### 3.2.2 读写编辑整理笔记

**读笔记**：

| 操作 | 工具 | 示例指令 |
|------|------|---------|
| 搜索 | `search_notes` | "搜一下包含'部署'的笔记" |
| 读全文 | `get_note` | "把《部署手册》这篇笔记读给我听" |
| 列任务 | `list_open_tasks` | "看看我还有什么任务没完成" |

**写笔记**：

| 操作 | 工具 | 示例指令 |
|------|------|---------|
| 新建 | `create_note` | "新建一篇笔记，标题是《今日总结》" |
| 追加 | `append_note` | "把这段内容追加到《工作笔记》末尾" |
| 整篇替换 | `replace_note` | "把《待办清单》整篇替换成新的内容" |

**编辑整理**：
- 整理要点："帮我把这篇笔记整理成三条要点"
- 合并笔记："把这三篇会议记录合并成一篇总结"
- 格式优化："帮我把这篇笔记的排版整理一下"
- 提取待办："从这篇会议记录里提取出待办事项，存成任务"

**写入三道闸门**（必须同时满足）：
1. 密钥必须是「读写」权限
2. 笔记开启「AI阅读」且非隐私
3. 笔记顶部点亮「允许外部智能体编辑」（新建默认开启）

##### 3.2.3 技能和工作空间存储

**目录结构**：

| 目录 | 作用 | 智能体权限 |
|------|------|-----------|
| 技能/ | 可复用的脚本、提示词模板、配置 | 可读写 |
| AI工作目录/ | 执行任务时的临时工作区 | 可读写 |
| 笔记附件/ | 笔记中上传的图片、附件 | 只读 |

**技能的使用**：
- 智能体执行任务前，先 `list_files` 查看「技能/」目录有没有可复用的
- 比如要写部署脚本，先看看「技能/」里有没有现成的模板
- 找到后 `read_file` 读取，基于已有技能修改

**技能的保存**：
- **不是自动保存**，需要你人工指示
- 你说："把这个脚本存到技能目录，以后可以复用"
- 智能体调用 `write_file` 保存到「技能/」
- 下次执行类似任务时自动复用

**工作目录的使用**：
- 智能体执行任务时生成的临时文件放在「AI工作目录/」
- 任务完成后，重要文件移到「技能/」或上传到笔记
- 临时文件定期清理

**二进制文件上传**：
- 图片、压缩包等二进制文件必须用 `get_upload_url` 获取上传地址
- 用curl POST上传，单文件上限1GB
- **禁止**用 `write_file` 写二进制（会变成base64灌进上下文）

---

##### 3.2.4 技能迁移和上下文传递（换计算机怎么办）

**技能迁移**：
- 技能存在MuseNote的「技能/」目录，不在本地计算机上
- 换计算机后，只要MuseNote还在，技能就还在
- 新计算机上的豆包配置好MCP后，直接 `list_files` 就能看到所有技能
- **不需要手动导出导入**，技能跟随MuseNote，不跟随客户端

**上下文传递**：
- 对话上下文存在豆包/workbuddy本地，换计算机后丢失
- 但**任务和结果存在MuseNote里**，不丢
- 换计算机后恢复工作的方法：
  1. 新计算机配置好MCP（同第三步）
  2. 对豆包说："去我的AI空间看看最近的笔记和任务，了解一下我在做什么"
  3. 智能体调用 `search_notes` + `list_open_tasks` 恢复上下文
  4. 继续工作

**最佳实践**：
- 重要的对话结论及时写回笔记（`append_note`）
- 常用的提示词和脚本存到「技能/」
- 这样换任何设备，只要能连MuseNote，就能恢复工作状态

##### 3.2.5 排错引导

**问题1：智能体不用MCP工具，乱七八糟调一堆**

**原因**：
- 系统提示词没配在全局，新对话忘了
- 提示词不够强硬，智能体优先用自己的内置能力
- MCP没连上，工具列表为空

**解决**：
1. **检查MCP连接**：在豆包设置里看MCP状态是否"已连接"，工具列表有没有musenote
2. **配全局提示词**：在豆包的**全局设置**里配系统提示词，不是单个对话
3. **提示词要强硬**：明确写"只能使用MCP工具，禁止使用任何内置工具，禁止凭记忆回答"
4. **对话开头确认**：新对话先说"你现在能访问我的AI空间吗？列出可用的MCP工具"，确认在线再用
5. **创建专用角色**：在豆包里建一个"我的AI空间助手"角色，默认带MCP提示词，以后直接选这个角色

**问题2：提示词配了，新对话又忘了**

**原因**：提示词只配在了某个对话里，没有配在全局

**解决**：
- 豆包：设置 → 系统提示词 → 配全局默认提示词
- workbuddy：设置 → 智能体配置 → 配全局
- 或者创建专用角色/智能体，默认带提示词
- 配好后，所有新对话自动生效

**问题3：搜索不到笔记**

**检查清单**：
- 密钥是否是读写权限（只读也能搜索）
- 笔记是否开启了「AI阅读」（关闭的笔记搜不到）
- 笔记是否是隐私笔记（隐私笔记搜不到）
- 向量化是否完成（新笔记可能还没索引）

**问题4：写入失败**

**检查清单**（三道闸门）：
- 密钥是「读写」权限吗？
- 笔记开启「AI阅读」了吗？
- 笔记顶部「允许外部智能体编辑」点亮了吗？
- 三个都满足才能写入

**问题5：MCP连接成功但调用报错**

- 检查密钥是否被撤销（MCP接入页面看状态）
- 检查MuseNote服务是否正常运行
- 检查网络是否能访问MuseNote的8765端口
- 传输类型选 HTTP / Streamable HTTP，不要选SSE（老客户端才用）

### 第4章：给智能体派任务

**学习目标**：在笔记里给智能体派任务，跟踪执行，查看回写结果。

**派任务的两种方式**：

**方式一：从任务块派单**
1. 在笔记里写好任务块（参考第2章）
2. 打开AI助手，切到「智能体」模式
3. 选择智能体，输入指令（或直接引用任务块）
4. 点发送
5. 智能体读取任务 → 执行 → 回写结果

**方式二：直接对话派单**
1. 打开AI助手，切到「智能体」模式
2. 直接输入任务描述，如「帮我搜索所有包含'部署'的笔记，整理成清单」
3. 智能体执行后回写到当前笔记或新建笔记

**任务执行过程**：
1. **接单**：智能体收到任务，开始执行
2. **执行中**：智能体可能搜索笔记、读文件、调用工具
3. **回写**：结果写入笔记（追加、替换、或新建）
4. **完成**：任务块标记完成，通知铃铛提醒

**任务状态**：
- 等待中 → 执行中 → 已完成 / 失败
- 在AI助手面板实时显示进度
- 完成后通知铃铛提醒
- 历史话题记录每次对话

**后台执行**：
- 智能体任务在服务端后台执行
- 关闭页面后任务继续运行
- 重新打开页面可以看到结果
- 可点「停止」中断执行

**多个智能体**：
- 可以绑定多个智能体
- 派任务时选择用哪个
- 不同智能体可以有不同的模型、提示词、能力
- 任务记录按智能体分开

**智能体能做什么**：
- 搜索和读取你的笔记
- 新建、追加、修改笔记内容
- 管理AI存储中的文件
- 执行命令（通过SSH）
- 调用外部API和工具
- 上传文件到笔记

**写好任务指令的技巧**：
- 明确目标：「整理成三条要点」比「总结一下」好
- 指定输出位置：「追加到这篇笔记末尾」比「写下来」好
- 提供上下文：「参考《部署手册》这篇笔记」
- 复杂任务拆成子任务

### 第5章：AI助手——快捷操作

> AI 助手是**快捷操作**——选中一段文字，立刻润色、翻译、讲解、归纳。
> 如果你想让 AI 帮你完成一个**任务**，看第4章「给智能体派任务」。

**学习目标**：使用AI助手对选中文字进行快速处理。

**AI助手的模型从哪来**：
- MuseNote 本身不部署大模型
- AI助手的排版、润色、翻译、讲解、归纳，全部通过绑定主站（云麓AI）的Muse服务，调用主站配置的模型
- 主站用什么模型，这里就用什么模型（在主站「模型管理」里切换）
- 绑定方式：设置 → 主站绑定 → 填入主站地址和通信令牌
- 绑定成功后，AI助手才能使用；未绑定时AI助手按钮置灰

**AI助手和智能体的区别**：

| | AI助手 | 智能体 |
|---|--------|--------|
| 定位 | 快捷操作 | 任务执行 |
| 输入 | 选中的文字 | 你写的任务描述 |
| 输出 | 处理后的文字 | 回写到笔记的完整结果 |
| 适合 | 润色、翻译、讲解 | 查资料、写代码、整理文档 |
| 章节 | 本章 | 第3-4章 |

**四大功能**：

| 功能 | 作用 | 输出方式 |
|------|------|---------|
| 智能排版 | 优化文字结构、标点、段落 | 预览版面，可继续编辑，确认后新建或替换 |
| 翻译 | 中英互译，短文本走离线词典 | 显示在原文尾部，原文自行处理 |
| 讲解 | 解释选中内容的含义 | 弹出讲解面板 |
| 归纳要点 | 提取核心观点和摘要 | 预览后用户决定插入页面 |

**智能排版**：
1. 选中要排版的文字
2. 点AI助手 → 智能排版
3. AI生成优化后的版本，显示在预览区
4. 预览区可继续手工编辑
5. 确认后选择：「新建笔记」或「替换原文」

**翻译**：
1. 选中要翻译的文字
2. 点AI助手 → 翻译
3. 短文本走内置离线词典，零流量秒回
4. 长段落走大模型翻译
5. 结果显示在原文尾部

**讲解 / 归纳**：
- 讲解：选中概念/代码/句子，AI用通俗语言解释
- 归纳：选中长文本，AI提取核心观点分条列出
- 结果可复制，可插入笔记

**AI助手对话**：
- 也可以直接和AI对话（不选中文字）
- 顶部「新话题」开启新对话
- 历史话题下拉切换
- 对话保存在服务端，换浏览器也能看到
- 输出支持Markdown渲染

**注意事项**：
- AI助手需要先完成「主站绑定」
- 大模型由主站提供，笔记站不单独部署
- 翻译短文本走离线词典，不消耗模型额度

### 第6章：AI存储——智能体的文件系统

**学习目标**：管理智能体的工作目录、技能文件、笔记附件。

**进入AI存储**：
- 左侧导航点「AI存储」
- 显示目录树和文件列表

**目录结构**：

| 目录 | 作用 | 智能体权限 |
|------|------|-----------|
| 技能/ | 存放可复用的脚本、提示词、配置 | 可读写 |
| AI工作目录/ | 智能体执行任务时的临时工作区 | 可读写 |
| 笔记附件/ | 笔记中上传的图片、附件 | 只读 |

**技能目录的使用**：
- 把常用的脚本、提示词模板放到「技能/」
- 智能体执行任务时优先在这里找参考
- 用户指定保存的技能，智能体自动同步一份到这里
- 技能文件可在多个智能体间共享

**AI工作目录**：
- 智能体执行任务时生成的临时文件放在这里
- 任务完成后重要文件应移到「技能/」或上传到笔记
- 定期清理不需要的临时文件

**文件操作**：
- 新建文件夹、上传文件、下载、删除（可恢复）、重命名
- 查看文本文件内容
- 整个文件夹可打包zip下载

**文件上传（智能体侧）**：
- 智能体通过MCP的 `get_upload_url` 获取上传地址
- 用curl POST上传二进制文件
- 单文件上限1GB
- 上传后文件出现在对应目录

**注意事项**：
- 「技能/」和「AI工作目录/」是智能体唯一可写的目录
- 不要把账号密码、API Key明文存到技能文件
- 归档技能时先把凭据替换成 `***`

**AI存储和任务的关系**：

```
你在笔记里写任务
   ↓
智能体接单执行
   ↓
执行过程中产生的文件 → 存到「AI工作目录/」
   ↓
可复用的脚本/提示词 → 你指示后存到「技能/」
   ↓
任务结果 → 写回笔记
```

- **任务执行时**：智能体在「AI工作目录/」里干活，生成的临时文件放这里
- **任务完成后**：结果写回笔记，重要文件移到「技能/」
- **下次执行类似任务**：智能体先去「技能/」找有没有可复用的
- **技能是资产**：存在MuseNote里，换计算机、换智能体都不丢

## 第三篇：MCP集成

### 第7章：MCP——外部智能体接入

**学习目标**：让外部智能体（CodeBuddy、豆包等）通过MCP协议访问你的工作空间。

**什么是MCP**：
- Model Context Protocol，模型上下文协议
- 外部AI智能体通过MCP连接到你的MuseNote
- 可以搜索、读取、创建、修改笔记
- 可以管理AI存储中的文件

**配置MCP接入**：
1. 个人设置 → MCP接入
2. 点「＋ 新建密钥」创建访问密钥
3. 密钥以 `mn_` 开头，是唯一凭证
4. 密钥分只读和读写两种权限

**MCP工具列表**：

**笔记相关**：
- `search_notes`：语义+关键词检索笔记
- `get_note`：按id或标题读笔记全文
- `create_note`：新建笔记（默认存入「MCP空间」）
- `append_note`：追加内容到笔记
- `replace_note`：整篇替换笔记内容
- `list_open_tasks`：跨笔记汇总未完成任务
- `complete_task`：标记任务完成

**文件相关**：
- `list_files` / `read_file` / `write_file` / `delete_file`
- `export_dir`：文件夹打包zip下载
- `get_upload_url`：二进制文件上传通道

**写入三道闸门**：
1. 密钥必须是「读写」权限
2. 笔记开启「AI阅读」且非隐私
3. 笔记顶部点亮「允许外部智能体编辑」（新建默认开启）

**MCP存储空间**：
- 每个账号默认自带一本「MCP空间」笔记本
- 外部智能体新建的笔记都落在里面
- 无需额外设置

**在CodeBuddy中配置**：
```bash
codebuddy mcp add-json --scope user musenote \
  '{"type":"http","url":"https://你的域名/mcp","headers":{"Authorization":"Bearer mn_你的密钥"}}'
```

**注意事项**：
- 密钥泄露等于笔记泄露，妥善保管
- 二进制文件必须用 `get_upload_url` 上传
- 可随时吊销密钥，吊销后立即失效

## 第四篇：协作

### 第8章：本地共享与协作

**学习目标**：在同一MuseNote实例内，与其他用户共享工作空间。

**共享笔记**：
1. 打开笔记 → 共享
2. 选择用户，设置权限：只读 / 可编辑
3. 本地用户和联邦用户在同一个下拉列表

**共享列表**：
- 左侧「共享」→ 我的共享 / 他人共享
- 显示笔记标题、共享对象、权限、时间

**协作编辑（共享块机制）**：

这是系统的核心设计。被共享者**不能直接改正文**，所有修改以「共享块」提交，主人审核后合并。

**为什么这样设计**：
- 主人对笔记有完全控制权
- 修改可追溯，接受/拒绝都有记录
- 多人协作不会互相覆盖

**修改块长什么样**：
- 被共享者插入的内容，显示为带边框的「待审核块」
- 块顶部显示：提交人、提交时间、接受/拒绝按钮
- 主人审核前，块一直保留在笔记中

**接受 / 拒绝**：
- 接受 → 共享块拆成普通内容，融入正文
- 拒绝 → 共享块从笔记中移除，对端同步移除

**被共享者的操作限制**：
- 可以插入新内容（文字、图片、表格、任务块等）
- 不能修改主人已有的正文
- 不能删除主人的内容
- 自己提交的待审核块可以撤回

**共享文件**：
- AI存储中的文件也可以共享
- 对方可以下载，撤销后无法下载

**通知机制**：
- 有人共享给你 → 通知提醒
- 对方提交修改 → 通知提醒
- 共享被撤销 → 通知提醒

### 第9章：联邦共享——跨工作空间协作

**学习目标**：跨MuseNote实例共享，实现多站点协作。

**为什么需要联邦**：

你和朋友各自部署了 MuseNote，数据都在自己手里。想共享怎么办？

- 给他一个你这边的账号 → 他的数据在你服务器上，他不放心
- 导出文件发给他 → 不同步，改了还要重新发
- **联邦** → 两台系统平等配对，各自数据在自己手里，按需共享

联邦的核心是**平等**：不是"你连到他的服务器"，而是两台独立系统建立信任关系。

**联邦建立流程**：

**第一步：管理员配对**
1. A站管理员：联邦管理 → 生成配对码
2. 6位数字配对码 + 本站URL，10分钟有效
3. 告诉B站管理员
4. B站管理员：输入对端URL + 配对码 → 配对成功

**第二步：设置联邦名称**
- 每个站点各自设置对端的显示名称
- 名称只在本站显示

**第三步：用户签署协议**
1. 配对成功后，所有用户收到通知
2. 用户：个人设置 → 联邦协议
3. 查看联邦列表（名称、状态、加入人数）
4. 点「签署加入」，阅读协议后确认

**共享给联邦用户**：
1. 打开笔记 → 共享
2. 联邦用户显示为「联邦名称/用户名」
3. 和本地用户在同一个列表，不分开
4. 设置权限：只读 / 可编辑

**数据同步机制**：
- 每60秒同步一次（同时作为心跳）
- 同步携带数据变更，不是空ping
- 文件和笔记生成哈希，确认变化才拉取
- 共享内容缓存在本地，镜像存储
- 镜像笔记不进搜索、不进向量化

**离线判定**：
- 连续5次同步失败（约5分钟）→ 判定离线
- 离线时：已共享内容本地可查看，但编辑锁定
- 提示「共享用户已离线，禁止编辑」
- 对方恢复后主动联络，认证通过后恢复

**解散联邦**：
- 管理员：联邦管理 → 解散
- 确认对话框说明后果：镜像内容将被删除
- 已被用户复制到本地的内容不受影响

**注意事项**：
- 联邦用户和本地用户体验一致，区别只是所有者前面加域名
- 复制联邦共享的内容到本地 → 变成本地文件，解耦不受限
- 更换对端URL需要重新配对

### 附录B：常见问题

**Q：智能体任务卡住了？**
A：在AI助手面板查看状态。任务在服务端后台运行，关闭页面不影响。可点「停止」中断。

**Q：MCP智能体写不进笔记？**
A：检查三道闸门：①密钥是读写权限 ②笔记开启AI阅读 ③笔记顶部「允许外部智能体编辑」已点亮。

**Q：智能体不用MCP工具，乱七八糟调一堆？**
A：①检查MCP是否连接成功 ②系统提示词配在全局（不是单个对话） ③提示词里明确写"只能使用MCP工具" ④新对话开头先让它"列出可用的MCP工具"确认在线。

**Q：提示词配了，新对话又忘了？**
A：提示词要配在智能体的**全局设置**里，不是单个对话。或者创建专用角色/智能体，默认带提示词。

**Q：联邦共享的内容打不开？**
A：检查对端是否在线（联邦管理看状态）。离线时内容只读，不可编辑。连续5分钟同步失败判定离线。

**Q：联邦配对失败？**
A：①确认6位码在10分钟有效期内 ②确认对方地址能访问（浏览器打开试试） ③确认双方都是管理员操作 ④配对码和地址绑定，换地址需要重新配对。

**Q：搜索不到新笔记？**
A：向量化默认每半小时扫描一次。可在设置中手动触发「立即重建索引」。

**Q：笔记内容没保存？**
A：笔记是自动保存的，底部状态栏显示保存状态。如果显示"保存失败"，检查网络连接，刷新页面会自动重试。

**Q：AI助手用不了？**
A：①检查主站绑定是否正常（设置 → 主站绑定） ②检查主站服务是否运行 ③AI助手需要主站提供大模型，笔记站不单独部署。

**Q：密码块内容忘了？**
A：密码块需要输入用户登录密码才能查看。如果忘了登录密码，管理员可以重置用户密码；但密码块的内容是用用户密码加密的，重置后密码块内容无法恢复。

**Q：删除的笔记能恢复吗？**
A：在「回收站」，可随时恢复，直到手动清空回收站。
