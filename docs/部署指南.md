# 云麓 Muse 部署指南

> 云麓 Muse = **云麓AI（工作流引擎）+ MuseNote（AI 笔记）**，两者强耦合，打包在**同一个容器**里交付。
> 本文给出一键容器化部署的完整步骤。所有示例中的镜像地址与路径均为占位，请替换为你自己的值。

## 一、前置要求

- 已安装 Docker 与 Docker Compose。**飞牛 fnOS、绿联 UGOS、群晖 DSM（Container Manager）、威联通 QTS（Container Station）、极空间 ZOS** 等国产 NAS 均自带 Docker 图形套件，可直接导入本 compose；普通 Linux（Ubuntu / Debian 等）装 `docker` + `docker compose` 插件即可。
- 建议资源：**≥ 2 核 / 4GB 内存 / 10GB 可用磁盘**（含本地模型时按需上调）
- 宿主开放的端口：见下方端口说明

## 二、端口说明

| 宿主端口 | 容器端口 | 服务 | 干什么用 |
|---|---|---|---|
| 4887 | 4887 | **MuseNote 笔记** | AI 笔记工作台主入口，浏览器直接访问这个 |
| 4888 | 4888 | **云麓AI 主站** | 工作流引擎的 Web 控制台（画布、执行、实体、设置） |
| 4889 | 4889 | **MuseApp 子站** | 智能体生成的低代码应用 / 页面运行时 |
| 8765 | 8765 | **MCP 接入服务** | 外部智能体（豆包 / 千问办公 / CodeBuddy 等）通过 MCP 协议连进来读写笔记与工作流的通道，端点 `:8765/mcp`、`:8765/musemcp` |

> 冒号左边是**宿主端口**（你机器上对外暴露的端口，被占用就改它），右边是**容器内部端口**（固定，不要改）。
> 只用笔记本体、不接外部智能体的话，8765 端口留着不影响，但**别删**——站内智能体功能也走它。

## 三、准备目录与配置文件

1. 新建一个部署目录，例如 `yunlu-muse/`。
2. 把仓库里的 [`deploy/docker-compose.yml`](../deploy/docker-compose.yml) 复制到该目录（或直接用下面的内容）。
3. 在该目录下建好数据卷对应的宿主机目录（首次部署会自动创建也可以）：

```
yunlu-muse/
├── docker-compose.yml
└── data/
    ├── ai-brain/      # 云麓AI 主站数据：工作流、执行记录、实体、设置、MCP 令牌
    ├── museapp/       # MuseApp 子站数据：智能体生成的应用 / 页面
    ├── upfile/        # 文件仓库：上传的图片/文档、客户端安装包、AI 存储的文件
    └── notedata/      # MuseNote 数据：笔记数据库、账号、AI 存储、技能（最关键的一份）
```

## 四、docker-compose.yml

```yaml
services:
  yulu-muse:
    image: <官方镜像地址>          # 换成你拿到的云麓Muse镜像地址，整行照抄即可
    container_name: yulu-muse
    restart: unless-stopped
    ports:
      - "4887:4887"   # MuseNote 笔记
      - "4888:4888"   # 云麓AI 主站
      - "4889:4889"   # MuseApp 子站
      - "8765:8765"   # MCP 智能体接入服务
    volumes:
      # ↓ 前两条：让容器和宿主机共用系统时间与所在时区，日志时间戳、定时任务才对得上；:ro 表示只读，容器改不了宿主时间
      - /etc/localtime:/etc/localtime:ro
      - /etc/timezone:/etc/timezone:ro
      # ↓ 后四条：把「数据」写到宿主机自己的 ./data 目录里，容器删了/升级了数据都不丢。
      #   格式是「宿主机路径:容器内路径」——冒号左边你可以随便改（比如换成 NAS 的存储路径），右边是程序固定的、不要动。
      - ./data/ai-brain:/usr/local/app/ai-brain/data            # 云麓AI 主站数据（工作流/执行记录/实体/设置/令牌）
      - ./data/museapp:/usr/local/app/ai-brain/museapp/data     # MuseApp 子站数据（智能体生成的应用/页面）
      - ./data/upfile:/usr/local/app/ai-brain/upfile            # 上传文件（图片/文档/安装包/AI 存储附件）
      - ./data/notedata:/usr/local/app/ai-brain/musenote/data   # MuseNote 数据（笔记库/账号/AI 存储/技能）
    environment:
      - TZ=Asia/Shanghai
    deploy:
      resources:
        limits:
          cpus: '4'
          memory: 3G
```

**数据卷都在存什么（重点看这几行）**

| 宿主机目录（可改） | 容器内路径（别改） | 里面装的东西 | 丢了会怎样 |
|---|---|---|---|
| `./data/ai-brain` | `/usr/local/app/ai-brain/data` | 云麓AI 主站的**全部配置**：工作流定义、执行历史、数据实体、系统设置、MCP 令牌 | 主站所有工作流和配置清空 |
| `./data/museapp` | `/usr/local/app/ai-brain/museapp/data` | MuseApp 子站生成的应用 / 页面数据 | 智能体做的应用丢失 |
| `./data/upfile` | `/usr/local/app/ai-brain/upfile` | 上传的图片、文档、客户端安装包、AI 存储里的文件 | 附件与安装包丢失 |
| `./data/notedata` | `/usr/local/app/ai-brain/musenote/data` | **MuseNote 的命根子**：笔记数据库、用户账号、AI 存储、技能库 | 所有笔记和账号清零 |

> 一句话：冒号**左边**是你机器上的真实目录，想放哪就放哪（NAS 用户常改成像 `/vol1/你的空间/data/...` 这样的路径）；冒号**右边**是程序内部写死的路径，改了起不来。首次启动 Docker 会自动把左边四个目录建出来，不用手动 `mkdir`。

## 五、启动

```bash
# 拉取并后台启动
docker compose up -d

# 查看运行状态与日志（确认起来了）
docker compose ps
docker compose logs -f yulu-muse
```

启动完成后：

- 云麓AI：`http://<服务器IP>:4888/`
- MuseNote：`https://<服务器IP>:4887/`（或 `http://<服务器IP>:4887/`）

## 六、数据与备份

- 全部持久化数据都落在 `./data/` 下的四个子目录，**迁移 / 备份只需打包这个目录**。
- 升级镜像：`docker compose pull && docker compose up -d`（数据卷不动，安全升级）。
- 数据库、密钥等敏感文件都在 `data/` 内，**请勿把整个 `data/` 目录提交到任何代码仓库**。

## 七、常见问题

- **端口被占用**：改 `ports` 左侧的宿主端口即可，容器内端口不要动。
- **内网 HTTP 访问被浏览器拦 Mixed Content**：给站点配 HTTPS 反向代理（Nginx/Caddy）更稳妥；桌面 / 移动客户端连自签证书时需在系统里信任该证书。
- **首次登录默认口令**：请通过环境变量 `MUSENOTE_DEFAULT_PASSWORD` 设定，不要沿用出厂默认值，装好后尽快改密。
