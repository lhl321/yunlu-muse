# 云麓 Muse 部署指南

> 云麓 Muse = **云麓AI（工作流引擎）+ MuseNote（AI 笔记）**，两者强耦合，打包在**同一个容器**里交付。
> 本文给出一键容器化部署的完整步骤。所有示例中的镜像地址与路径均为占位，请替换为你自己的值。

## 一、前置要求

- 已安装 Docker 与 Docker Compose（NAS / Linux 均可；群晖、威联通等支持 Container Manager 的设备同样适用）
- 建议资源：**≥ 2 核 / 4GB 内存 / 10GB 可用磁盘**（含本地模型时按需上调）
- 宿主开放的端口：见下方端口说明

## 二、端口说明

| 宿主端口 | 容器端口 | 用途 |
|---|---|---|
| 4888 | 4888 | 云麓AI 主站（Web 控制台 + 工作流） |
| 4887 | 4887 | MuseNote 笔记 |
| 4889 | 4889 | 附加服务（按你的网关/反代需要） |
| 8765 | 8765 | 附加服务（按需要） |

> 左侧（宿主端口）可按你机器上已被占用的端口自行修改，容器内部端口保持不变。

## 三、准备目录与配置文件

1. 新建一个部署目录，例如 `yunlu-muse/`。
2. 把仓库里的 [`deploy/docker-compose.yml`](../deploy/docker-compose.yml) 复制到该目录（或直接用下面的内容）。
3. 在该目录下建好数据卷对应的宿主机目录（首次部署会自动创建也可以）：

```
yunlu-muse/
├── docker-compose.yml
└── data/
    ├── ai-brain/      # 云麓AI 数据
    ├── museapp/       # MuseApp 数据
    ├── upfile/        # 上传 / 安装包
    └── notedata/      # MuseNote 数据
```

## 四、docker-compose.yml

```yaml
services:
  yulu-muse:
    image: <你的镜像仓库地址>/yulu-muse:<版本号>
    container_name: yulu-muse
    restart: unless-stopped
    ports:
      - "4888:4888"
      - "4889:4889"
      - "4887:4887"
      - "8765:8765"
    volumes:
      - /etc/localtime:/etc/localtime:ro
      - /etc/timezone:/etc/timezone:ro
      - ./data/ai-brain:/usr/local/app/ai-brain/data
      - ./data/museapp:/usr/local/app/ai-brain/museapp/data
      - ./data/upfile:/usr/local/app/ai-brain/upfile
      - ./data/notedata:/usr/local/app/ai-brain/musenote/data
    environment:
      - TZ=Asia/Shanghai
    deploy:
      resources:
        limits:
          cpus: '4'
          memory: 3G
```

## 五、启动

```bash
# 若镜像在需要登录的私有仓库，先登录
docker login <你的镜像仓库地址>

# 拉取并后台启动
docker compose up -d

# 查看运行状态与日志
docker compose ps
docker compose logs -f yulu-muse
```

启动完成后：

- 云麓AI：`http://<服务器IP>:4888/`
- MuseNote：`https://<服务器IP>:4887/`（或 `http://<服务器IP>:4887/`）

## 六、数据与备份

- 全部持久化数据都落在 `./data/` 下的四个子目录，**迁移 / 备份只需打包这个目录**。
- 升级镜像：`docker compose pull && docker compose up -d`（数据卷不动，安全升级）。
- 数据库、密钥等敏感文件都在 `data/` 内，**请勿把整个 `data/` 目录提交到任何代码仓库**。

## 七、常见问题

- **端口被占用**：改 `ports` 左侧的宿主端口即可，容器内端口不要动。
- **内网 HTTP 访问被浏览器拦 Mixed Content**：给站点配 HTTPS 反向代理（Nginx/Caddy）更稳妥；桌面 / 移动客户端连自签证书时需在系统里信任该证书。
- **首次登录默认口令**：请通过环境变量 `MUSENOTE_DEFAULT_PASSWORD` 设定，不要沿用出厂默认值，装好后尽快改密。
