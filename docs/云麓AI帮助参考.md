# 快速开始

欢迎使用云麓AI智能体工作流平台。本帮助文档将帮助你快速上手平台的使用。

## 平台界面介绍

平台主要由以下几个页面组成：

- **编辑器**：工作流的可视化编辑页面，左侧是节点库，中间是画布，右侧是执行日志
- **管理后台**：工作流管理、模型配置、服务集成、用户管理等
- **帮助中心**：当前页面，提供使用指南和API文档

## 创建第一个工作流

1. 点击顶部导航的「编辑器」进入工作流编辑页面
2. 从左侧节点库拖拽一个**触发器节点**（如定时触发）到画布
3. 拖拽一个**输出动作节点**（如小米控制）到画布
4. 从触发器节点的右侧输出端口，拖拽连线到输出节点的左侧输入端口
5. 双击节点配置参数（如定时时间、要控制的设备）
6. 点击顶部「保存」按钮保存工作流
7. 点击「启用」按钮启用工作流，即可自动运行

工作流必须「启用」后才会自动触发。保存只是保存配置，不会自动运行。

可以随时点击节点上的「运行」按钮手动测试单个节点。

## 画布操作

- **拖拽节点**：从左侧节点库拖拽到画布
- **移动节点**：按住节点头部拖拽
- **连线**：从节点右侧输出端口拖拽到目标节点左侧输入端口
- **删除连线**：点击连线后按Delete键
- **删除节点**：选中节点后按Delete键
- **缩放画布**：鼠标滚轮缩放
- **平移画布**：按住空白处拖拽
- **折叠节点**：点击节点头部的折叠按钮
- **多选节点**：按住 `Shift` 键点击节点可多选，选中后可整体拖拽移动
- **批量复制**：多选节点后右键 → 复制，或按 `Ctrl+C`
- **批量删除**：多选节点后按 `Delete` 键，会弹出确认对话框

画布左下角有操作提示：按住 Shift 点击可多选节点。

## 服务集成

平台支持多种第三方服务集成，需要在「管理后台 → 服务配置」中先启用并配置：

- **小米集成**：小米设备事件监听、状态查询、设备控制
- **HomeAssistant**：HA实体状态查询、服务调用、事件监听
- **MQTT**：MQTT消息订阅和发布
- **SMTP邮件**：发送邮件通知
- **高德地图**：路况播报等位置服务

服务启用后，对应的节点才会出现在左侧节点库中。

# 核心概念

## 工作流

工作流是由多个节点通过连线组成的自动化流程。当触发器节点被激活时，整个工作流会按照预设的逻辑自动执行。

每个工作流有「启用」和「禁用」两种状态，只有启用状态的工作流才会自动触发。

### 项目复制

在项目列表页，右键点击项目 → 「复制项目」，可快速创建一个项目副本：

- 复制后的项目名称为「原项目名 复制1」「原项目名 复制2」…
- 复制出的项目**默认禁用**，避免与原项目同时运行产生冲突
- 可在编辑页修改名称后启用

### 不记录日志

在项目编辑页，可开启「不记录日志」选项：

- 开启后，该工作流执行时不写入节点执行日志
- 适用于高频触发、数据同步类工作流，减少日志存储
- 关闭后恢复正常日志记录

## 节点

节点是工作流的基本单元，每个节点执行特定的功能。节点分为以下几类：

| 分类 | 说明 |
| --- | --- |
| 触发器 | 工作流的起点，如定时触发、事件触发、手动触发等 |
| AI能力 | AI文本生成、AI判断等 |
| 数据处理 | 数据实体读写、字符串拼接、数据运算、数据提取等 |
| 逻辑控制 | 条件判断、多条件分支、延时、循环等 |
| 项目节点 | 项目入口、项目调用，实现工作流之间的嵌套引用 |
| 输出动作 | HTTP请求、邮件发送、小米设备控制、HA服务调用等 |
| 记忆与知识 | 记忆读写、记忆映射、知识读取与插入等 |
| 媒体输入 | RTSP摄像头抓图、图片下载等 |

## 连线与端口

节点之间通过连线连接，表示数据流向和执行顺序。

- **输入端口**：节点左侧的圆点，接收上游数据
- **输出端口**：节点右侧的圆点，向下游传递数据
- **分支端口**：部分节点有多个输出端口（如判断节点的「满足」和「不满足」），根据条件选择不同路径
- **命名端口**：部分节点有特定名称的输入端口（如AI生成的 text_in 和 image_in）

从同一个节点分出多条连线，这些分支会并行执行。AI生成节点会自动等待所有上游节点执行完成后再开始。

## 数据实体

数据实体是全局共享的数据存储，可以在不同工作流之间传递数据。支持以下类型：

- **字符串**：文本数据
- **数字**：数值数据
- **布尔值**：true/false
- **对象**：JSON对象

数据实体在「管理后台 → 数据实体」中管理，工作流中通过「数据实体」节点读取或写入。

## 变量引用

在节点配置中，可以使用 `{{变量名}}` 的格式引用上游节点的输出或数据实体。

推荐使用节点配置中的「选择字段」按钮，自动生成正确的变量路径，避免手动输入错误。

# 执行器原理

## 执行顺序

工作流从触发器节点开始执行，沿着连线向下游传递。当一个节点的所有上游节点都执行完成后，该节点才会开始执行。

- **普通节点顺序执行**：一个普通节点的输出口连了多个下游时，下游节点按连线顺序依次执行，不是并行
- 节点会等待所有非惰性上游完成后再执行
- 分支不匹配的上游节点会被标记为「跳过」，不影响下游
- **惰性数据源**：数据实体、读取记忆、知识注入等节点，**没有入边时**不计入上游等待数，由下游节点执行前按需激活读取；**如果连了上游**，则不再是惰性源，必须等上游完成才执行

## 并行与异步机制

平台支持多种并行/异步执行模式，适用于不同场景：

### 1. 并发子项目（真正的并行）

当一个节点的输出口连接了**多个项目调用节点**时，这些子项目会**并发执行**，而不是顺序执行。

- 父节点执行完成后，同时启动所有下游子项目
- 父工作流挂起等待，等所有子项目都完成后才继续执行后续节点
- 子项目执行完成后，各自的输出数据会汇总到父节点的输出中
- 子项目内可以再嵌套子项目，递归支持并发
- 系统自动检测循环引用（A→B→A），检测到后报错，不会死循环
- 单个项目调用节点行为不变，与之前版本完全一致

只有**多个项目调用节点**才会并发。如果一个输出口连了多个普通节点（如判断、数据处理），仍然是顺序执行。多条件判断节点的多个分支出口也不是并行，只有匹配的那个分支会执行。

### 2. 循环节点（异步迭代）

循环节点每次迭代在**独立线程**中异步执行，不阻塞调度器和其他工作流。

- 循环启动后注册调度器定时任务，每次触发时创建独立执行实例
- 上一次迭代还在运行时，新的迭代会被跳过（并发保护）
- 循环内的变量状态在迭代之间共享，通过循环状态传递
- 达到最大次数后触发「达到上限」分支并自动停止

### 3. 延时节点（非阻塞延时）

延时节点通过调度器注册定时任务，**不占用执行器线程**，下游节点在指定时间后执行。

- 延时期间，同一工作流的其他分支可以继续执行
- 延时时间支持变量引用，可以动态设置延时时长
- 延时节点本身立即返回，不会阻塞工作流执行队列

### 4. 等待Webhook / 项目调用（挂起恢复）

等待Webhook回调节点和项目调用节点会**挂起当前工作流**，等回调或子项目完成后恢复执行。

- 挂起期间不占用执行器线程，工作流保留在运行列表中
- 有超时机制，超时后自动恢复并标记超时状态
- 回调到达时，从挂起点继续执行后续节点

### 并行模式对比

| 模式 | 是否并行 | 适用场景 | 阻塞父工作流 |
| --- | --- | --- | --- |
| 并发子项目 | 是 | 多个独立任务同时执行 | 是（等全部完成） |
| 循环迭代 | 异步 | 重复执行任务 | 否（独立线程） |
| 延时节点 | 非阻塞 | 等待一段时间 | 否（调度器定时） |
| 等待Webhook | 挂起 | 等外部回调 | 是（挂起等待） |
| 普通多下游 | 否 | 顺序执行多个节点 | — |

## 分支逻辑

部分节点有多个输出分支，根据条件选择执行路径：

- **判断节点**：条件满足走「满足」分支，不满足走「不满足」分支
- **多条件判断**：按顺序匹配条件，走第一个满足的分支，都不满足走「否则」分支
- **任一条件**：任一条件满足走「满足」分支，都不满足走「不满足」分支
- **循环节点**：每次循环走「每次」分支，达到最大次数走「达到上限」分支

### 分支阻断规则

如果一个节点的入边中有来自分支节点（判断、多条件判断、AI判断等）的**分支端口**（matched/unmatched），且没有任何一条分支边匹配，则该节点会被阻断，不执行。

知识注入、读取记忆、数据实体等「无上游、自动执行」的惰性节点，即使连到了被阻断的节点，也不会解除阻断。只有分支端口匹配的边才能驱动该节点执行。

例如：判断走「不满足」时，「满足」端口下游的节点即使连了知识注入等惰性数据源，也不会执行。

## 数据传递规则

每个节点执行后会产生输出数据，下游节点可以引用这些数据。输出数据结构统一为：

```
{
  "data": { ... },      // 本节点产生的数据
  "input": { ... },     // 上游节点的数据（透传）
  "inputs": {           // 按节点ID区分的上游数据
    "node_xxx": { ... },
    "node_yyy": { ... }
  },
  "result": true/false, // 判断类节点的结果
  "matched": "c1"       // 多条件判断匹配的分支
}
```

`data`：本节点产生的数据，是最常用的引用字段

`input`：上游节点的数据透传，用于追溯原始数据

`inputs`：按节点ID区分的上游数据，多个上游时用这个区分

`result`：判断节点的布尔结果

## 惰性数据源与AI节点穿透

**惰性数据源的判断规则：**

- 节点类型属于数据源清单（数据实体、读取记忆、知识注入、RTSP抓图、系统提示词等）
- **且没有任何入边** → 惰性源，被下游引用时自动激活
- **如果有入边** → 不是惰性源，必须等上游完成才执行，上游没激活则不启动

**AI节点一级穿透：**

- AI文本生成/AI判断节点的直接上游如果是纯数据处理节点（数据提取、数据运算、字符串拼接）
- 且这个中间节点的所有上游都是惰性数据源（无入边）
- 则AI节点执行前会先激活中间节点，中间节点再激活惰性数据源
- **只穿透一级**：AI→数据处理→数据源（2级）可以；AI→数据处理1→数据处理2→数据源（3级）不行
- 多级数据处理请封装到子项目中

## 循环节点详解

循环节点通过「开始循环」端口启动，每隔指定时间触发一次「每次」分支。可以设置最大次数，达到后走「达到上限」分支并自动停止。通过「停止循环」端口可以提前停止。

### 循环执行原理

- 循环节点收到「开始循环」信号后，注册调度器定时任务，**首次循环至少2秒后执行**（确保启动触发有足够时间执行完并保存变量状态）
- 每次循环触发时，创建独立的工作流执行实例，从循环节点开始执行下游
- 循环迭代在独立线程中异步执行，不阻塞调度器和其他工作流
- 上一次迭代还在运行时，新的迭代会被跳过（并发保护），等上一次完成后自动排期下一次
- 达到最大次数后，触发「达到上限」分支，然后自动停止循环

### 循环内变量状态传递

内部变量在循环迭代之间是**共享的**，通过以下机制传递：

1. 循环启动时，把当前执行上下文的内部变量保存到循环状态
2. 启动触发执行结束时，把变量状态更新到循环节点（确保开始时间等变量被保存）
3. 每次循环触发时，从循环状态恢复上一次迭代的变量值
4. 每次迭代执行结束时，把更新后的变量保存回循环状态

在启动触发时写入「开始执行时间」变量，循环内累计「成功次数」变量，循环结束后在邮件中引用这些变量生成执行报告。

循环/定时配置修改后，需要**禁用再启用**工作流才会生效。保存按钮旁有提示。

## 工作流启用/禁用

禁用工作流时：

- 停止定时触发任务
- 取消事件订阅（小米、HA、MQTT等）
- 停止所有循环任务
- 正在执行的工作流会继续跑完，不会强制中断

# 数据与变量

## 变量引用格式

在节点配置中，使用 `{{路径}}` 引用数据。支持单花括号 `{data}` 和双花括号 `{{data}}` 两种格式。

## 字段选择器

大部分节点的配置项旁边都有「选择字段」按钮，点击后会弹出上游节点的输出数据列表，选择后自动生成正确的变量路径。

手动输入变量路径容易出错，推荐使用「选择字段」按钮自动生成。选择器会按 data、input、inputs 分类显示所有可用字段。

## 常用变量路径

| 路径 | 说明 |
| --- | --- |
| {{data}} | 当前节点上游产生的数据（最常用） |
| {{data.字段名}} | 上游数据中的某个字段 |
| {{inputs.node_xxx.data}} | 指定上游节点的数据 |
| {{result}} | 判断节点的布尔结果 |
| {{matched}} | 多条件判断匹配的分支名 |

## 内部变量

内部变量是工作流执行期间的临时变量，**纯内存存储**，工作流执行完自动释放。和数据实体用法一致，但作用域仅限于当前工作流。

### 创建变量

从左侧节点库拖拽「内部变量」节点到画布，选择「新增变量」，填写变量名和初始值。支持三种数据类型：

- **字符串（string）**：文本内容，初始值留空为空字符串
- **数字（number）**：数值，初始值留空为 0
- **布尔（boolean）**：真/假，初始值留空为 false

支持英文和中文，不能以数字或特殊符号开头。变量名在工作流内唯一，重复创建会失败。

### 变量卡片形态

- **悬浮卡**：创建变量后，画布顶部会出现悬浮变量卡，显示变量名和当前值，鼠标悬停可查看详情。右键可编辑或删除。
- **实体卡**：拖拽「使用内部变量」节点到画布，和数据实体一样的逻辑，可以读取或写入变量。

### 读写变量

内部变量实体卡支持两种模式：

- **读取模式**：输出变量当前值到 `data` 字段
- **写入模式**：把上游值或指定值写入变量，支持以下操作：
  - 数字：设置值、+1、-1、+、-、×、÷
  - 字符串：设置值、追加内容
  - 布尔：设置开、设置关、切换

### 变量引用

在所有节点的字段选择器中，内部变量会置顶显示，可以直接选择引用。也可以手动输入 `{{变量名}}` 引用。

删除变量前会检查是否有其他节点引用，有引用时不能删除。变量改名后，引用该变量的卡片名称会同步更新。

## 数据实体节点

数据实体节点用于读取或写入全局数据实体：

- **读取模式**：读取指定数据实体的当前值，输出到 `data` 字段
- **写入模式**：将上游数据写入指定数据实体

布尔类型的数据实体在画布上会根据值显示不同颜色（绿色=true，红色=false）。

## 字符串拼接

字符串拼接节点用于组合多个变量和固定文本。在模板中使用 `{{变量名}}` 引用上游数据。

例如模板：`今日天气：{{今日天气.data}}，在家人员：{{在家人员.data}}`

## 数据运算

数据运算节点（运算符节点）支持对数据进行各种运算处理：

### 操作数来源

运算符的两个操作数都支持三种来源：

- **固定值**：直接填写常量
- **上游数据**：通过字段选择器选择上游节点的输出字段
- **内部变量**：选择已创建的内部变量

### 支持的运算

| 数据类型 | 运算 | 说明 |
| --- | --- | --- |
| 数字 | 设置值 | 直接赋值 |
| +、-、×、÷ | 四则运算 |
| +1、-1 | 自增/自减 |
| 计算时间差 | 两个时间字符串的差值，输出秒/分钟/小时 |
| 取模 | 取余数 |
| 字符串 | 设置值 | 直接赋值 |
| 追加 | 在末尾追加内容 |
| 布尔 | 设置开/关 | 直接赋值 true/false |
| 切换 | 取反 |
| 与/或 | 逻辑运算 |

### 时间差运算

选择「计算时间差」运算时，两个操作数都应为时间格式字符串（如 `2026-09-05 12:00:00`），输出为时间差值，可选择单位：秒、分钟、小时。

如果运算出错（如时间格式不正确），节点输出 `result=false`，日志中会记录错误信息，下游判断节点可据此处理。

在内部变量写入或字符串拼接中，使用 `{{now}}` 可插入当前时间。邮件模板中使用 `{date:now}`。

# 触发器节点

触发器是工作流的起点，每个工作流必须有至少一个触发器。

## 定时触发

**配置项：**

- **触发规则**：支持每天指定时间、间隔执行、自定义Cron表达式
- **排除规则**：设置不触发的时间段

## 手动触发

用于测试或需要手动启动的场景。

## Webhook触发

**基本配置：**

- **Webhook名称**：触发URL的路径，如 `/api/你的名称`
- **输入类型**：字符串、数字、布尔值、对象

**认证配置：**

- **不认证（默认）**：无需认证即可调用。可勾选启用IP白名单，限制允许访问的IP地址
- **应用认证**：从「管理后台 → 应用授权」中选择已创建的应用，调用时需携带认证信息。可勾选启用独立IP白名单（覆盖应用级白名单）

**调用方式：**向 `http://平台地址/api/名称` 发送POST请求，请求体会作为触发数据传入。

应用授权支持两种方式：Key认证（API Key）和用户认证（用户名密码登录获取Token）。一个应用可被多个Webhook引用，统一管理认证和IP白名单。详见「管理后台 → 应用授权」。

## 小米事件触发

需要先在「服务配置」中启用小米集成。选择要监听的设备和属性，当设备状态变化时触发工作流。

## HA事件触发

需要先在「服务配置」中启用HomeAssistant集成。

**配置项：**

- **实体ID**：要监听的HA实体，如 `input_boolean.xxx`
- **从状态**：可选，状态从这个值变化时触发（留空=任意）
- **到状态**：可选，状态变化到这个值时触发（留空=任意）

## MQTT触发

需要先在「服务配置」中启用MQTT服务。

## 启动触发

项目从「禁用」变为「启用」时，若画布中存在该节点，会自动执行一次它所在的链路。

- 手动点「启用」、项目启停节点/AI项目管理节点启用、HA 工作流控制绑定打开，都会触发一次
- 保存工作流不会触发（保存不等于启用）；服务重启后仍处于启用状态的项目也会执行一次
- 典型用途：开机/重启后拉取天气、节假日等公共数据，或初始化内部变量

# AI能力节点

## AI文本生成

**输入端口：**

- `text_in`：文本输入，连接提供文本数据的节点（数据实体、知识库、字符串拼接等）
- `image_in`：图片输入，连接图片节点（RTSP抓图、图片下载），仅多模态模型支持

**配置项：**

- **模型**：选择要使用的AI模型（在管理后台配置）
- **提示词**：生成文本的指令，支持变量引用
- **系统提示词**：可选，连接系统提示词节点设定AI角色

1. 提供数据的节点（知识库、天气、数据实体等）直接连接到 text_in，不需要经过判断节点

2. 判断节点只用于控制是否执行，不接数据端口

3. AI生成节点会自动等待所有上游节点执行完成

4. 图片必须连接到 image_in 端口，文本连接到 text_in 端口

5. 输出的生成内容在 `data` 字段

### 必须有图像输入才执行

适用于监控类场景：只有当 image_in 端口有图像输入时才执行AI生成，无图时跳过下游（不触发邮件、播报等后续节点）。

- 默认关闭，不影响现有项目
- 开启后，无图像输入时节点标记为「跳过」，不触发下游
- 常用于「目录扫描 → AI分析 → 邮件通知」链路：没图时整条链路停止

## AI判断

**输入端口：**

- `text_in`：判断依据的文本
- `image_in`：判断依据的图片（仅多模态模型）

**输出分支：**

- **满足**：AI判断条件成立
- **不满足**：AI判断条件不成立

系统提示词已内置，不需要额外连接系统提示词节点。输出结构包含 `result`（布尔值）和 `reason`（判断原因）。

## AI多条件判断

**输入端口：**

- `text_in`：判断依据的文本（为空时自动收集上游文本）
- `image_in`：判断依据的图片（仅多模态模型）

**配置项：**

- **模型**：选择AI模型，建议选择多模态模型以支持图片输入
- **输入文本**：可选，手动输入判断依据，支持变量引用
- **判断条件**：动态添加多个条件，每个条件只需填写判断描述（如"文本中是否提到有人"）

**输出端口：**

- 根据条件数量动态生成 `c1`、`c2`、`c3`... 端口
- 条件满足时对应端口导通，**多个条件可同时满足**（多端口同时导通）
- 所有条件都不满足时，所有端口都不导通

**输出数据：**每个条件输出 `result`（布尔值）和 `reason`（判断理由）

普通「多条件判断」是按顺序匹配，走第一个满足的分支；「AI多条件判断」是AI一次性判断所有条件，**多个条件可同时满足**，对应多个端口同时导通。

多个端口同时导通时，下游按端口顺序（c1→c2→c3...）依次执行，画布上连线上会显示执行序号。不是并行执行。

## AI选择分支

**输入端口：**

- `text_in`：选择依据的文本（为空时自动收集上游文本）
- `image_in`：选择依据的图片（仅多模态模型）

**配置项：**

- **模型**：选择AI模型，建议选择多模态模型以支持图片输入
- **输入文本**：可选，手动输入选择依据，支持变量引用
- **选项列表**：动态添加多个选项，每个选项只需填写描述（如"播放音乐"、"打开灯光"）

**输出端口：**

- 根据选项数量动态生成 `c1`、`c2`、`c3`... 端口
- AI选择哪个选项，对应端口就导通，**只有一个端口导通**
- 如果AI解析失败，默认选择第一个选项

**输出数据：**`selected`（选中的选项编号）、`selected_label`（选项描述）、`reason`（选择理由）

「AI多条件判断」是判断多个条件是否成立，可同时满足；「AI选择分支」是从多个选项中选一个，只有一个导通。

## 系统提示词

连接到AI文本生成节点的 text_in 端口，作为系统提示词使用。可以选择预设模板或自定义内容。

# 数据处理节点

## 数据实体

**配置项：**

- **实体名称**：选择要操作的数据实体
- **操作类型**：读取 / 写入
- **写入模式（数值型）**：
  - **运算符**：设置 / 加 / 减 / 乘 / 除
  - **值来源**：上游数据 / 固定值
    - 上游数据：从上游节点取值作为操作数
    - 固定值：直接输入常量作为操作数（如每次+1）

读取模式下，实体值输出到 `data` 字段。布尔类型实体在画布上会显示颜色（绿=true，红=false）。

固定值功能仅在**写入模式**且**数值类型**下生效。读取模式下固定值不生效。

无上游输入的数据实体是惰性数据源，不计入下游等待数，由下游执行前按需激活读取。

## 字符串拼接

在模板中使用 `{{变量名}}` 引用上游数据。拼接结果输出到 `data` 字段。

## 数据运算

**支持的运算：**

- **替换**：将上游数据替换为固定值或另一个变量
- **数值运算**：加、减、乘、除
- **字符串处理**：截取、大小写转换等

## 数据提取

通过字段路径提取数据，支持使用「选择字段」按钮自动生成路径。提取结果输出到 `data` 字段。

## 设置数据

**配置项：**

- **类型**：字符串 / 数字 / 布尔
- **值**：对应类型的常量值

上游触发后输出配置的值，**下游只能连接数据实体节点**。

## RTSP抓图

**配置项：**

- **名称**：摄像头名称
- **RTSP地址**：摄像头的RTSP流地址
- **超时时间**：抓取超时（毫秒）
- **画质**：JPEG压缩质量（0-100）

输出的图片数据可以连接到AI生成节点的 image_in 端口。节点配置中可以点击「抓取」按钮测试。

## 图片读取

**图片来源：**

- **图片库选择**：从已保存的图片库中挑选固定图片
- **引用上游路径**：用路径选择器引用上游输出的图片路径，例如微信消息触发的 `{{微信消息触发.file_path}}`，可选中所有上游（含间接上游）

**输出：**图像数据（base64，可连 AI 生成节点的 image_in 端口）与文件路径。

## 目录扫描

常用于「目录扫描 → AI 分析 → 邮件/微信通知」链路。没有文件时整条链路停止，可配合判断节点做兜底。

**配置：**目录、文件类型/扩展名匹配、数量上限；输出文件路径列表（可直接连 AI 节点图片输入）。

## 目录同步

用于「图片累积区 → 处理区」的批量搬运：先把上一批残留清空，再把新文件整体复制过去，避免重复处理。

**配置：**源目录、目标目录、文件匹配规则。

## 下载/保存图片

**配置：**图片 URL / base64 来源、保存目录、文件命名（可加时间戳）、压缩质量、水印文字与位置。

输出保存后的本地文件路径，供后续发送或识别使用。

## ONVIF摄像头

在「服务配置」中填写摄像头的 ONVIF 地址、账号密码后，可在节点中选择设备并抓图，输出图像数据，可连 AI 节点图像输入。

# 逻辑控制节点

## 条件判断

**配置项：**

- **判断来源**：上游数据 / 内部变量
  - 上游数据：通过字段路径选择上游节点的输出字段
  - 内部变量：直接选择已创建的内部变量，无需连线
- **数据类型**：字符串、数字、布尔值
- **运算符**：
  - 数值型：大于、小于、等于、大于等于、小于等于、不等于、**在区间内**、**不在区间内**
  - 字符串型：等于、不等于、包含、不包含、开头是、结尾是、为空、不为空
  - 布尔型：为真、为假
- **区间判断**（数值型）：选择「在区间内」或「不在区间内」后，显示最小值和最大值输入框
  - 最小值/最大值留空表示该侧不限
  - 每个边界可勾选「包含」（闭区间 ≥/≤）或不勾选（开区间 >/<）
  - 支持4种区间：[min,max]、(min,max)、[min,max)、(min,max]
- **比较值来源**：常量 / 数据实体 / 内部变量 / 随机值（仅数字类型）
  - 常量：直接输入固定值
  - 数据实体：从全局数据实体取值
  - 内部变量：从工作流内部变量取值
  - 随机值：在指定范围内生成随机数（仅数字类型）

**输出分支：**满足（matched）/ 不满足（unmatched）

判断结果在 `result` 字段（布尔值），实际输入值在 `input_value` 字段。

选择「内部变量」作为判断来源后，直接选择变量名即可，不需要把变量节点连到判断节点。变量值会在执行时自动读取。

## 多条件判断

可以添加任意多个条件，每个条件对应一个输出分支。都不满足时走「否则」分支。

每个条件的配置与「条件判断」节点一致，支持区间判断（在区间内/不在区间内）。

匹配结果在 `matched` 字段（如 c1、c2、else）。

## 任一条件

只处理已经导通的上游条件，任一为真即走「满足」分支，都不为真走「不满足」分支。未导通的上游会被忽略，不参与判断。

## 全部条件

**要求所有入边对应的上游都必须导通**，有一个上游没触发（被跳过或分支没走到），直接走「不满足」分支，不会判断其他条件的值。

所有上游都导通后，再检查所有判断结果是否都为真，全部为真才走「满足」分支。

**全部条件**：有一个上游没导通 → 直接失败

**任一条件**：没导通的上游被忽略，只看导通的

如果某个条件可能不触发，又希望其他条件能正常判断，请用「任一条件」或给该条件加触发源。

## 任一事件

支持动态添加多个事件输入。任一上游有值即走「满足」分支，全部无值走「不满足」分支。

## 全部事件

支持动态添加多个事件输入。所有上游都有值才走「满足」分支，否则走「不满足」分支。会等待所有上游执行完成。

## 时间判断

**配置：**

- **重复类型**：每天、工作日、周末、自定义星期
- **时间段**：可添加多个时间段；支持跨天（如 22:00 ~ 次日 06:00）

**输出分支：**在范围内（matched）/ 不在范围内（unmatched）。

## 延时等待

非阻塞实现，不会影响其他并行分支。支持秒、分钟、小时单位。

## 循环

**输入端口：**

- `start`（绿色）：开始循环，必须连接到此端口才会启动
- `stop`（红色）：停止循环

**输出分支：**

- **每次**（out）：每次循环触发，执行下游节点
- **达到上限**（max_reached）：达到最大次数后触发，循环自动停止，下游节点会正常继续执行
- **手动停止**（stopped）：收到stop信号后触发，循环停止，下游节点会正常继续执行

「达到上限」和「手动停止」分支触发后，连接的下游节点会正常执行，并继续向下传递。例如：达到上限 → 小米控制 → 选择器 → 小米控制，整条链路都会执行。

**配置项：**

- **间隔时间**：支持固定值或 `{{random(min,max)}}` 随机间隔
- **时间单位**：秒、分钟、小时
- **最大循环次数**：0=无限次

### 执行原理

- 收到 start 信号后注册调度器任务，**首次循环至少2秒后执行**
- 每次循环在独立线程异步执行，不阻塞其他工作流
- 上一次迭代未完成时，新迭代会被跳过（并发保护）
- 内部变量在循环迭代之间共享，每次迭代结束后保存状态

### 循环内变量

内部变量在循环迭代之间自动传递：启动时保存初始值，每次迭代结束后更新，下一次迭代开始时恢复。可用于累计计数、记录开始时间等。

1. 循环/定时配置修改后，需禁用再启用工作流才会生效。

2. 连线时必须连接到 `start` 端口，空端口连线不会启动循环。

3. 循环内的延时节点会独立排期，不影响循环间隔计时。

## 最多触发次数

每执行一次计数 +1，未达到上限时走「执行」分支继续下游；达到上限后走「已达上限」分支并停止放行。计数在工作流运行期间累计，重启/重新启用后清零。

## 达到指定次数

每来一次信号计数 +1，达到设定次数时走「达到」分支（可用于事件聚合、去抖）；未达到时走「未达到」分支。可配置达到后是否清零重新计数。

# 项目节点

项目节点用于实现工作流之间的嵌套引用，一个工作流可以调用另一个工作流作为子流程，类似函数调用。

## 项目入口

**特点：**

- 本身不会主动触发，只能被其他项目调用
- 一个项目可以有多个项目入口，每个入口对应不同的下游分支
- 包含项目入口的项目不能引用其他项目（防止循环嵌套）

**接收字段：**

- 可自由定义接收字段（如 `zdy`、`zdy2`），调用方通过路径选择器映射上游数据
- 接收字段不能是保留字段（`data`、`input`、`result` 等）
- 默认不接收数据，需要手动添加
- 保证不同调用方传入的数据字段一致性，子项目无需感知上游具体节点

**输出设置：**

- 默认返回 `true`/`false`，表示子项目整体执行成功或失败
- 所有节点都执行成功 = `true`，任一节点报错/失败 = `false`
- 可自定义返回字段，通过路径选择器选择本项目产生的数据字段
- 返回的数据属于调用方项目的 `data`（本节点产生的数据）

## 项目调用

**配置项：**

- **目标项目**：下拉列表只显示包含项目入口的项目，且不包含自身
- **项目入口**：选择目标项目中的具体入口节点
- **数据引入**：根据目标入口定义的接收字段，通过路径选择器将上游数据映射到对应参数

**执行逻辑：**

- 项目调用节点会**等待子项目全部执行完成**后才继续下游
- 支持 `text_in`、`image_in` 等多输入端口，与普通节点一致
- 子项目执行完成后，输出端才会触发下游

**并发子项目调用：**

- 当一个节点的下游**全部是项目调用节点，且超过1个**时，这些子项目会**同时启动并发执行**
- 等所有子项目都完成后，才统一通知下游继续执行
- 并发连线在画布上显示为**蓝色虚线 + ∥ 符号**
- 如果下游混合了项目调用和其他普通节点，则保持原有串行执行顺序
- 单个项目调用节点行为不变，与之前版本完全一致
- 子项目内可再嵌套并发组，递归自动生效
- 系统自动检测循环引用（A→B→A），检测到后直接报错，不会死循环

**嵌套限制：**

- 包含项目入口的项目不能引用其他项目
- 引用了其他项目的项目不能添加项目入口
- 不支持反复嵌套调用

**快捷操作：**节点卡片上有「打开项目」按钮，点击直接跳转到被调用的子工作流进行编辑。

## 批量异步派发

**配置项：**

- **目标项目 / 项目入口**：要循环派发的子项目及其入口
- **数据源**：上游数组，例如审批列表
- **元素变量名**：默认 `item`，参数映射里用 `{{item.字段}}` 表示当前元素
- **参数映射**：把子项目入口的接收字段映射到当前元素的字段
- **超时**：单个子任务的最长等待时间（默认 1800 秒）

**执行逻辑：**

- 对数组的每个元素启动一个子项目实例，相邻两次派发间隔约 0.5 秒错峰，避免瞬间并发
- 每个子项目可独立挂起（如等待微信引用回复），互不影响
- 节点等待所有子任务结束（barrier），再按下标顺序收集结果，主工作流才继续

**输出字段：**`results`（每项结果数组，按下标）、`total`、`success_count`、`fail_count`、`text`（汇总文本）。

上游给出多张待审批单，批量异步派发把每张单派给同一个「发微信 → 等待引用回复 → 审批」子项目；多个审批人可同时回复，全部处理完后再汇总。解决了「同一工作流一次只能处理一单、上一单未处理下一单进不来」的问题。

## 项目启停

**配置：**目标项目、动作（启用 / 禁用 / 切换）。

- 启用一个含「启动触发」的项目时，会顺带执行一次启动链路
- 启停状态变更会同步刷新调度器定时任务，并与 HA 工作流控制绑定保持一致

## AI项目管理

**输入：**文本输入（可接微信/音箱触发的用户原话）。

**配置项：**

- **模型**：用于解析意图的 AI 模型（留空用默认）
- **提示词**：可自定义解析提示词
- **允许动作**：启用 / 禁用 / 查询状态，可勾选开放哪些
- **包含子项目**：匹配时是否把被引用的子项目也纳入候选
- **匹配阈值**：名称相似度门槛，低于阈值视为未匹配，返回疑似项目列表

**输出：**一个 `text` 字段，把动作、项目名、结果（成功/已是该状态/未找到/疑似列表）拼成一段通俗文字，可直接接微信发送节点。

**返回模式：**可在节点上选择「模板返回」或「AI 生成回复」；支持批量查询（如"查询所有打开的项目"）。找不到项目不报失败，便于下游继续发通知。

## 执行与日志

- 项目调用节点的执行日志显示子项目整体成功/失败
- 详情中可查看子项目各节点的执行状态
- 子项目内部各节点的详细日志在子项目编辑页各自查看
- 数据传递遵循统一规则：本节点产生的数据在 `data`，上游透传数据在 `input`/`inputs`

## 典型使用场景

把多个工作流共用的逻辑（如发送通知、数据清洗、API调用封装）抽成子项目，其他工作流通过项目调用复用，避免重复配置。

复杂工作流拆分成多个子项目，每个子项目负责一个功能模块，主工作流通过项目调用串联，便于维护和调试。

循环节点的每次分支可以调用同一个子项目，传入不同的参数，实现批量处理。子项目的内部变量在每次调用时独立，不会互相干扰。

## 注意事项

包含项目入口的项目不能引用其他项目，引用了其他项目的项目不能添加项目入口。不支持反复嵌套调用（A调B，B不能调A）。

项目调用节点会**等待子项目全部执行完成**后才继续下游。如果子项目里有长延时或循环，会阻塞主工作流的后续执行。

子项目的内部变量是独立的，主工作流的内部变量不会自动传入子项目。需要通过项目入口的接收字段显式传递。

# 脚本管理

脚本节点允许你执行自定义 Python 代码，扩展平台能力。每个脚本可以包含多个入口函数，通过 `@yunlu` 装饰器标记。

脚本在独立子进程中执行，有超时限制（默认30秒），文件访问被限制在脚本专属目录内，确保安全隔离。

## @yunlu 装饰器

只有被 `@yunlu` 装饰器标记的函数才会出现在脚本节点的「函数入口」下拉列表中，可被工作流调用。未标记的函数是内部函数，只能在脚本内部调用。

```
@yunlu
def hello(name: str):
    """这个函数会出现在入口列表中"""
    return {"message": f"你好，{name}"}

def _helper(x):
    """这个函数不会出现在入口列表中"""
    return x * 2
```

## 函数参数自动解析

脚本节点会自动解析函数签名，根据参数名、类型标注和默认值动态生成参数输入框。

| 类型标注 | 前端控件 | 说明 |
| --- | --- | --- |
| str | 文本输入框 | 默认类型，无标注时也按 str 处理 |
| int | 文本输入框 | 执行时自动转换为整数 |
| float | 文本输入框 | 执行时自动转换为浮点数 |
| bool | 是/否下拉 | 支持 true/false/1/0/yes/no 等 |

有默认值的参数为可选，无默认值的参数为必填（标红星）。参数值支持 `{{上游引用}}` 变量替换。

```
@yunlu
def example(name: str, count: int = 3, enabled: bool = True):
    """name 必填，count 和 enabled 可选"""
    return {"name": name, "count": count, "enabled": enabled}
```

## 返回值

函数 `return` 的字典即为脚本节点的输出，下游选择器会自动识别字段。建议始终返回字典，并包含 `success` 字段表示执行结果。

```
@yunlu
def do_something():
    try:
        result = 1 + 1
        return {"success": True, "result": result}
    except Exception as e:
        return {"success": False, "error": str(e)}
```

如果函数没有 return 或 return None，下游可能拿不到数据，日志中会有警告。

## 内置工具函数

平台内置了一些需要系统权限的工具函数，脚本中可以**直接调用**，不需要 import，也不需要 subprocess（subprocess 已被禁止）。

### ping_check(devices, thresholds=None)

对设备列表执行 Ping 测试（仅 Linux 环境），返回各设备的延迟和状态。

- **devices**：设备列表，每个元素可以是 `{"name": "名称", "ip": "IP"}`、`["名称", "IP"]` 或 `"IP"`
- **thresholds**：自定义阈值，默认 `{"excellent": 20, "good": 50, "poor": 100}`
- **返回**：`{"设备名": {"status": "优秀/良好/差/中断", "delay": "5ms/超时"}}`

```
@yunlu
def check_network():
    result = ping_check([
        {"name": "路由器", "ip": "192.168.1.1"},
        {"name": "百度", "ip": "www.baidu.com"},
        "8.8.8.8"
    ])
    return {"success": True, "result": result}
```

### udp_send(host, port, data, timeout=2)

发送 UDP 数据包。

- **host**：目标IP或域名
- **port**：目标端口
- **data**：发送的数据（字符串或bytes）
- **timeout**：超时秒数，默认2
- **返回**：`{"success": True/False, "sent": 发送字节数, "error": 错误信息}`

```
@yunlu
def send_udp():
    result = udp_send("192.168.1.100", 8080, "hello")
    return {"success": result["success"], "sent": result["sent"]}
```

### tcp_send(host, port, data, timeout=2, receive=False)

发送 TCP 数据，可选接收响应。

- **host**：目标IP或域名
- **port**：目标端口
- **data**：发送的数据（字符串或bytes）
- **timeout**：超时秒数，默认2
- **receive**：是否接收响应，默认False
- **返回**：`{"success": True/False, "sent": 发送字节数, "received": 接收的数据, "error": 错误信息}`

```
@yunlu
def send_tcp():
    result = tcp_send("192.168.1.100", 80, "GET / HTTP/1.0\r\n\r\n", receive=True)
    return {"success": result["success"], "response": result.get("received", "")}
```

### ai_vision(requirement, images=None, model_id='', system_prompt='')

调用平台已配置的大模型，专门做**纯文本问答、图片理解**。无需 import、无需密钥，直接调用；任何错误都通过返回值给出，不会中断脚本。PDF / Word / Excel / PPT 等文档请改用 `doc_recognize()`。

- **requirement**：识别要求或提问（必填），例如“提取单据全部文字与金额”。
- **images**：可空。`None`=纯文本；字符串=单个；列表=多个（图片最多 3 张）。元素支持：
  - 沙箱内图片路径：`.jpg/.jpeg/.png/.webp/.bmp/.gif`
  - `http(s)://` 图片链接
  - `data:image/...;base64,` 或裸 base64
- **model_id**：可空，自动选默认模型。纯文本用默认文本模型；含图片时用默认多模态模型，**不会自动降级到文本模型**（没配多模态模型会直接报错）；显式指定的模型若不支持图片也会报错。
- **system_prompt**：可选系统提示词。
- **返回**：统一字典。成功为 `{"success": True, "text": 结果文本, "model": 模型名, "model_id": 模型ID, "count": 图片张数, "error": None, "note": 备注}`，纯文本 count=0；失败为 `{"success": False, "text": "", "error": 原因, ...}`。

```
# 1) 纯文本问答
r = ai_vision("用一句话解释什么是 JWT")
if r["success"]:
    print(r["text"])

# 2) 识别多张图片（路径 / 链接 / base64 均可，最多3张）
r = ai_vision("提取发票上的全部字段和总金额", ["invoice1.jpg", "invoice2.jpg"])
if r["success"]:
    print(r["text"])
else:
    print("识别失败：", r["error"])
```

### doc_recognize(file_path, requirement='', model_id='', pdf_batch=3, pdf_max_batches=3, pdf_dpi=200, image_limit=10, pdf_page_limit=None)

识别**文档**：PDF、Word（doc/docx/rtf/odt/wps）、Excel（xls/xlsx/csv/ods/et）、PPT（ppt/pptx/odp/dps）。一次一个文件，无需 import、无需密钥，错误通过返回值给出。

- **file_path**：沙箱内文档路径（相对脚本目录或沙箱绝对路径），也支持 `data:application/pdf;base64,` 开头的 PDF。
- **requirement**：识别要求/提问，可空（用默认提示）。
- **model_id**：可空，自动选默认多模态模型；走视觉识别时指定的模型必须是多模态。
- **pdf_batch / pdf_max_batches / pdf_dpi**：仅对**扫描件 PDF / PPT** 的视觉渲染生效（数字 PDF 走文本层、不渲染）。按每批 3 个图块、最多 3 批（共 9 页）以 200dpi 渲染，超大页自动纵向切块（带重叠），超过 9 页只识别前 9 页并在 note 注明；小字模糊可在脚本里把 pdf_dpi 调到 220/300。
- **image_limit**：Word / Office 内嵌图片的识别张数上限，默认 10、填 0 禁用图片识别（仅提取文字），最大 500；每张图一次多模态调用，图片越多越慢、越耗模型。
- **pdf_page_limit**：PDF / PPT 视觉识别的**总页数**上限（正整数，最大 300）。填写后按总页数自动换算批次，不再受 pdf_batch×pdf_max_batches 默认 9 页的限制，例如 `pdf_page_limit=30` 识别前 30 页；留空沿用默认 9 页。脚本侧不支持 0 禁用（仅知识库界面支持禁用视觉）。
- **智能分流**：
  - **Excel / CSV**：直接解析单元格，按“工作表 + 行列”输出，**不消耗模型**，数字/日期准确；每个工作表最多 200 行，内嵌图片不识别（note 提示）。
  - **纯文字 Word**：直接提取段落与表格文本，**不消耗模型**。
  - **含图片的 Word（docx）**：文字直接提取，内嵌图片按**原始分辨率逐张**交给多模态识别（不做 A4 缩放，截图小字也清晰），结果按图片在文中的位置（`【图片N】`）合并；识别张数由 `image_limit` 控制（默认 10 张，可调大到 500，0=不识别图片）。
  - **数字 PDF（电子发票、电子合同、PDF 导出的文档）**：直接读取 PDF 自带的**文本层**，**不消耗模型**，金额/数字/日期/税号 100% 准确，不会因整页 OCR 漏读密集小字。
  - **扫描件 PDF / 图片版 PDF**：无文本层的页才渲染成 200dpi 高清图块（超大页纵向切块）交给多模态；同一份 PDF 若部分页有文本层、部分页是扫描图，会自动按页分流再合并。
  - **PPT、老格式 Word（doc/rtf/odt/wps）**：渲染成页面图像交给多模态模型识别。
- **返回**：与 ai_vision 同一字典结构。直接解析 / 数字 PDF 文本层时 `model` 标注“直接解析 / PDF文本层提取（未走视觉）”、count=0；扫描件/PPT 走视觉时 count 为识别页数；含图 Word 时 count 为识别的图片张数。

```
# 1) Excel：直接读出表格数据（不耗模型）
r = doc_recognize("报名表.xlsx")
if r["success"]:
    print(r["text"])        # 【工作表：Sheet1】（N 行）\n姓名 | 部门 | ...
    print(r.get("note"))    # 截断/内嵌图片等提示
else:
    print("识别失败：", r["error"])

# 2) PDF / Word：数字 PDF 直接读文本层（金额准确），扫描件/含图 Word 走视觉
r = doc_recognize("报销单.pdf", "逐页提取文字、费用明细和金额，保留表格结构")
if r["success"]:
    print(r["text"])
    if r.get("note"):
        print(r["note"])    # 例如：PDF 共 15 页，仅识别前 9 页
else:
    print("识别失败：", r["error"])
```

图片/文档只能读取脚本自己沙箱目录（`upfile/scripts/脚本ID/`）内的文件。图片识别用 `ai_vision`；PDF/Office 文档识别用 `doc_recognize`，Office 转换依赖容器内置的 LibreOffice、PDF 渲染依赖 pypdfium2，视觉识别会消耗多模态模型额度。

内置函数由平台安全封装，脚本无法直接调用 subprocess/socket 等系统模块。如需其他系统级工具，请联系平台扩展内置函数。

## 脚本存储目录隔离

每个脚本有独立的存储目录：`upfile/scripts/脚本ID/`。脚本中的相对路径都基于此目录解析，可以自由读写文件（如保存 cookie、缓存数据等）。

- 删除脚本时，整个存储目录会被一并删除
- 不同脚本之间无法互相访问文件
- 脚本无法访问目录之外的文件系统

```
@yunlu
def save_cookie():
    # 文件保存在 upfile/scripts/脚本ID/cookie.txt
    with open("cookie.txt", "w") as f:
        f.write("my_cookie_value")
    return {"success": True}
```

## 脚本目录管理

在管理后台「脚本管理」页面，每个脚本卡片上有一个「目录」按钮，点击可打开文件管理器，管理该脚本存储目录下的文件。

- **上传文件**：从本地上传文件到脚本目录
- **下载文件**：下载脚本目录下的文件到本地
- **删除文件**：删除脚本目录下的文件
- **文件列表**：显示文件名、大小、修改时间

上传 cookie 文件、配置文件、证书等供脚本读取；下载脚本生成的结果文件、日志文件等。脚本中的相对路径就是相对于这个目录。

## Class 使用

脚本内可以自由定义 class，用于组织代码。class 仅在脚本内部使用，不会出现在入口列表中。入口函数可以创建 class 实例并调用其方法。

```
class Calculator:
    def __init__(self, precision=2):
        self.precision = precision

    def add(self, a, b):
        return round(a + b, self.precision)

@yunlu
def calculate(a: float, b: float):
    calc = Calculator(precision=2)
    return {"result": calc.add(a, b)}
```

## 脚本节点配置

**配置项：**

- **选择脚本**：从已创建的脚本中选择
- **函数入口**：选择该脚本中某个 @yunlu 函数
- **脚本参数**：根据选中函数的签名自动生成输入框
- **超时（秒）**：脚本执行超时时间，默认30秒

## 注意事项

- **无状态**：每次脚本执行是独立子进程，变量和类实例无法跨节点、跨执行共享。需要共享状态请用文件（cookie.txt 等）或内部变量节点
- **print 输出**：脚本中的 print 会被捕获，显示在节点执行日志中
- **超时**：超过超时时间脚本会被强制终止，返回超时错误
- **threading**：允许使用 threading 模块，但整个进程有超时限制，超时后所有线程都会被终止
- **禁止**：不允许导入 subprocess、multiprocessing、sys、Flask 等高风险模块

## 完整示例

```
# -*- coding: utf-8 -*-
"""
脚本示例：包含 class、内部函数、两个入口函数
"""
import json
import time

# class 示例：仅脚本内部使用
class Counter:
    def __init__(self):
        self.count = 0

    def increment(self):
        self.count += 1
        return self.count

# 内部函数：不会出现在入口列表
def _format(msg):
    return f"[{time.strftime('%H:%M:%S')}] {msg}"

# 入口函数 1
@yunlu
def greet(name: str, times: int = 1):
    """返回问候语"""
    counter = Counter()
    messages = []
    for i in range(times):
        n = counter.increment()
        messages.append(_format(f"你好，{name}！第{n}次"))
    return {
        "success": True,
        "message": "\n".join(messages),
        "count": times
    }

# 入口函数 2
@yunlu
def calc(a: float, b: float, op: str = "add"):
    """简单计算"""
    if op == "add":
        result = a + b
    elif op == "sub":
        result = a - b
    else:
        result = 0
    return {"success": True, "result": result}
```

# 记忆与知识

## 记忆系统概述

记忆系统采用分层摘要架构，自动整理历史记忆，支持按分类独立配置：

- **原文**：原始记忆条目，按分类存储
- **日摘要**：每日自动合并当天原文为一条摘要
- **周摘要**：每周自动合并日摘要为一条摘要
- **月摘要**：每月自动合并周摘要为一条摘要
- **年摘要**：每年自动合并月摘要为一条摘要

周摘要按 ISO 自然周归并（周一为一周开始、周日为周末锚点），月摘要锚定当月最后一天、年摘要锚定 12 月 31 日；只汇总已经结束的完整周期，避免一周还没结束就只生成当天内容。

记忆库、知识库、提示词、数据实体均已整合到编辑器页面，点击顶部导航即可打开弹窗管理。

## 记忆写入节点

**输入端口：**1个（内容输入）

**配置项：**

- **节点名称**：自定义节点显示名称（留空使用默认）
- **分类**：记忆分类，支持变量引用 `{{xxx}}`
- **内容来源**：自动收集 / 指定上游路径 / 固定文本
- **指定路径**：内容来源为"指定上游路径"时填写，如 `inputs.node_xxx.output.data`
- **固定文本**：内容来源为"固定文本"时填写，支持变量引用

记忆自动记录时间戳，无需手动插入时间。

## 记忆读取节点

**配置项：**

- **节点名称**：自定义节点显示名称（留空使用默认）
- **分类筛选**：点选标签多选，不选=全部
- **关键词**：可选，支持变量引用，定向召回相关原文
- **时间范围**：今天 / 最近3天 / 最近7天 / 最近30天 / 最近90天 / 最近180天 / 最近1年 / 全部
- **返回条数**：最多返回多少条原文

**输出：**

- `memory_text`：格式化文本，带【历史记忆】引导和分类标签，可直接注入AI提示词
- `events`：原始事件数组

读取时自动合并原文和各层摘要（日/周/月/年），时间范围内优先读原文，更早的读对应层级摘要。

## 记忆分类配置

在编辑器页面点击顶部「记忆库」打开管理窗口，可配置每个分类的独立设置：

- **是否归纳**：开启后该分类的记忆会参与自动整理；关闭后超出窗口的原文直接删除、不生成摘要
- **汇总方式**：
  - **按时间（日/周/月/年）**：适合长期记忆，每日自动合并当天原文为日摘要，每周合并日摘要为周摘要，依此类推
  - **按条目（上下文窗口）**：保留最近 N 条原文作为上下文，超出的每 M 条合并为 1 条摘要；可启用级联（一级摘要满了再压成二级摘要）
- **按时间模式参数**：摘要层级（日/周/月/年可多选）、原文保留天数、摘要保存周期
- **按条目模式参数**：保留最近 N 条原文（默认20）、每 M 条合并为摘要（默认10）、级联开关及参数
- **专用提示词**：该分类整理时的自定义需求（基础格式内置不可修改）
- **独立模型**：该分类整理时使用的AI模型（默认用全局模型）
- **映射到知识库**：开启后把该分类的摘要（不汇总的档案类为原文）自动同步为知识库同名只读文档并参与向量检索，详见下文「记忆映射到知识库」

自动整理需要凑满一整批（原文达 N+M 条才触发），实际保留区间是 [N, N+M-1]。

手动「立即整理」会强制压缩，不受"凑批"限制，零头也会一起压掉。

## 自动整理

系统每日00:00自动执行记忆整理：

- 按分类独立整理，分类间互不干扰
- 按时间模式：只整理已结束的周期（如今天的原文等到明天才整理）
- 按条目模式：原文超过 N+M-1 条才自动压缩（凑满一整批）
- 整理失败后1小时重试，最多5次
- 整理日志记录在「管理后台 → 系统日志」中

也可以手动执行立即整理：选择需要整理的分类后确认执行。

**参与判断**：扫描到的候选记录总数（含各层级摘要），不等于会生成摘要

**生成摘要**：实际新生成的摘要条数

**删除旧记录**：被删除的原记录/旧摘要条数

**跳过**：未达到触发条件而跳过的记录数（如按条目模式未凑满一批）

如果"生成摘要=0 且 跳过=0"，说明本次没有需要压缩的内容（相关分类的条目数还没超过触发线）。

## 记忆映射到知识库

对于希望用「语义检索」来召回的记忆分类（如家庭事件、重要记录），可在该分类的整理设置里开启**「映射到知识库」**。开启后系统会把该分类的内容全量同步成一个知识库同名文档（标记为「记忆映射」），并自动建立向量索引。

- **同步内容**：按时间汇总的分类同步日 / 周 / 月 / 年摘要；不汇总的档案类（如家庭档案）同步原文；按条目汇总的分类同步一 / 二级摘要。原始流水不搬，仍留在记忆库。
- **只读同源**：映射文档在知识库侧只读，不能编辑、不能删除；内容的唯一源头是记忆库，在记忆库修改后会自动重新同步并重做向量化。
- **避免重复**：已映射的摘要层不再由「读取记忆」节点注入 AI，改由「读取知识」语义检索提供，同一段摘要不会重复喂给模型；未映射的分类与流水仍走记忆库。
- **自动维护**：每日 / 手动整理后、按条目模式压缩生成摘要后、记忆人工增改删后（防抖）、开关保存时都会自动同步；系统启动时还会做一次补偿对齐（修复此前因服务异常造成的漏同步）；关闭开关即删除对应映射文档，重新开启会自动重建。
- **分类同名**：知识库分类随记忆库分类自动同名建立，无需单独维护。

把「家庭事件」映射到知识库后，问「昨天几点回来的」这类问题，会由读取知识节点语义检索到对应的日摘要来回答；近期原文流水仍由记忆库提供。

## 读取知识

**读取模式：**

- **全量注入**：把所选分类的文档整篇注入，可设最大字符数，适合资料量小、需要完整上下文的场景。
- **语义检索**：按「问题」做向量 + 全文混合检索，只返回最相关的若干片段，可设返回片段数（top_k）与分类范围。

**语义检索的问题来源**（四选一）：

- **自动收集上游文本**：连接上游节点，自动汇总上游输出文本（默认）。
- **内部变量**：选择一个工作流内部变量作为问题。适合读取知识节点**不连入边、作为惰性数据源**被 AI 唤醒的场景——先用一个挂在主链路的内部变量节点把问题写入变量，读取知识节点再从该变量取问题。
- **指定上游路径**：按字段路径取指定上游的值，如 `node_xxx.data.text`。
- **固定问题**：写死一个检索问题。

检索采用**向量语义 + 关键词全文（BM25）混合**，以向量为主并按相似度阈值过滤，专有名词、精确措辞也能命中。执行日志会显示检索模式、向量模型、命中数（向量命中 / 关键词命中）。

知识库在编辑器页面顶部「知识库」弹窗中管理。读取结果通常连接到 AI 生成节点的 text_in 端口。

## 知识插入

**配置：**目标分类与文档、内容来源（自动收集上游 / 指定路径 / 固定文本）、写入方式。

- **末尾追加**：在文档末尾换行追加新内容（默认）。
- **覆盖替换**：用本次内容整体替换文档。
- **文档不存在时自动新建**：可开关，目标文档不存在时按标题自动创建。

无论追加、替换还是新建，写入后都会**自动重新向量化**，无需手动重建；在知识库管理里做的手动整理回写后也会自动重新索引。

与「读取知识」配对，可实现知识的自动沉淀，例如把每天的事件摘要自动追加到某个知识库文档。记忆库自动投影的「记忆映射」文档为只读，不能由本节点或人工改写。

## 知识库与向量模型

知识库的语义检索依赖**向量模型**把文本转成向量，再按相似度召回。向量来源在「后台管理 → 模型管理」里唯一的一张向量模型卡片上切换，三选一：

- **内置本地向量（默认）**：系统内置 Qwen3-Embedding-0.6B（INT8 量化 ONNX 版），以独立本地服务（127.0.0.1:11143，OpenAI / Ollama 双协议）随主站启动，输出 1024 维归一化向量。模型权重放在挂载目录，离线可用、不依赖外网，常驻内存约 1 GB。
- **Ollama**：填写本机或局域网的 Ollama 地址与模型名（如 qwen3-embedding:0.6b），适合已有 Ollama 环境或想用 GPU 的场景。
- **OpenAI 兼容**：填写任意兼容 OpenAI `/v1/embeddings` 接口的地址、密钥与模型名。

**切换向量来源后需重启系统并重建全部向量**：不同模型生成的向量不通用，系统会在重启后自动清空旧向量、按新模型重建全部知识库文档（含记忆映射文档）；重建期间语义检索可能暂时为空，属正常现象。

### 文档解析与索引维护

上传 PDF / Word / Excel / PPT 后点「解析」会弹出解析选项，可控制视觉识别成本：

- **图片识别上限**：Word 内嵌图片的识别张数，默认 10、填 0 禁用图片只提取文字、上限 500；每张图一次多模态调用。
- **PDF 识别页数**：扫描件 / PPT 的视觉识别页数，默认 30、填 0 禁用视觉只取文本层（纯扫描件会无内容）、上限 300；数字 PDF 始终走文本层、不耗模型。
- **用大模型整理段落结构**：合并断行、还原标题与表格、清理排版标记，更慢且耗模型；不勾选则直接解析原文。

编辑文档时：**只改分类不会使向量失效**（分类不参与向量与全文索引，只作检索过滤），系统会同步更新已有块的分类、保持「已向量化」状态；只有改了**标题或正文**才需要重新向量化。保存时可选择「保存并向量化」或「仅保存」。

### 本地向量服务与资源

内置向量模型以独立的本地服务进程（127.0.0.1:11143）运行，与主站分离，模型加载或批量向量化不会阻塞主站；常驻内存约 1 GB，使用 CPU 推理。

- 推理线程数与分片按容器**实际可用 CPU 核数自动检测**（读取 cgroup 限额，容器限核时按限额走），并对在线检索优先、批量向量化让路，避免大批量重建时把检索请求拖到超时。
- 需要手动指定时可用环境变量 `EMBED_THREADS`（每分片线程数）、`EMBED_SHARD`（分片数）覆盖自动检测。

### 文档切片口径

入库前文档会按语义标题切成块再逐块向量化，切片按**中文字符数**（不是 token）计算：目标块约 600 字、硬上限 800 字、相邻块重叠 80 字、小于 80 字的块自动并入相邻块。

Qwen3-Embedding-0.6B 的上下文长度为 **32768 token（约 32K）**，输出 1024 维。中文实测约 0.66~0.73 token / 字，800 字的硬上限块约 500~600 token，远低于 32K，**不会被截断**，无需按上下文长度调小切片。

# 微信集成

## 概述

通过微信 ClawBot（iLink 协议）实现微信消息的接收和发送，支持多账号管理：

- **微信消息触发**：收到微信消息时自动触发工作流
- **微信发送消息**：向指定微信用户发送文本和图片
- **多账号**：支持添加多个微信账号，独立轮询、独立绑定
- **文件自动下载**：收到的图片/语音/视频等自动下载到本地

## 账号配置

在「管理后台 → 微信 ClawBot」中管理账号：

1. 点击「添加账号」，输入账号名称（如 jeff）
2. 点击「绑定」，扫码登录微信
3. 绑定成功后，用该微信向 Bot 发送第一条消息，系统自动记录用户ID
4. 账号列表显示：账号名称、绑定状态、用户ID

用户ID（to_user_id）格式为 `xxx@im.wechat`，需要用户主动向 Bot 发送一条消息后才能自动获取。

未获取用户ID前，账号列表会提示"请向微信发送第一条消息"。

## 文件保存路径

收到的媒体文件（图片/语音/视频等）自动下载并解密，保存路径：

`upfile/weixin/{账号名}/{YYYY-MM-DD}/{时间戳}_{文件名}`

触发器输出的 `file_path` 字段为相对于 upfile 目录的相对路径，可直接被其他节点引用。

## 微信消息触发节点

**配置项：**

- **监听账号**：checkbox 多选，不选=监听全部账号

**输出字段：**

- `text`：消息文本内容（图片/语音等消息显示为 [图片]/[语音]）
- `from_user_id`：发送者用户ID（`xxx@im.wechat`）
- `time_str`：消息时间（如 2026-09-15 10:30:00）
- `context_token`：会话上下文 token（回复消息时可回传）
- `account_id`：接收消息的账号名称
- `account_name`：账号名称（同 account_id）
- `file_path`：附件文件相对路径（文本消息为空）
- `file_type`：附件类型（image/voice/video/file）
- `file_name`：附件文件名

## 微信发送消息节点

**输入端口：**1个（上游数据输入，用于变量引用）

**配置项：**

- **账号来源**（二选一）：
  - **选择账号**：checkbox 多选已绑定账号，支持"全部用户"选项；查库取绑定者用户ID发送
  - **引用变量**：变量值直接作为接收者用户ID（如 `{{微信消息触发.from_user_id}}`），不查库；发送账号用第一个已绑定的账号
- **消息内容**：支持变量引用，留空则只发图片
- **图片**：
  - **发送图片 / 不发图片**：单选
  - **图片路径**：留空=自动从直接上游取图片；可填 upfile 相对路径、绝对路径、base64（多行/逗号分隔，支持多张）
- **会话上下文 Token**（可选）：回复场景填 `{{微信消息触发.context_token}}`；不填用最近活跃会话

**发送顺序：**先逐张发图片，再发文本。每条消息间隔约 1.5 秒，规避微信约 6 条/60 秒的频率限制。

**图片路径格式（三种都支持）：**

- **相对路径**：如 `weixin/jeff/2026-09-15/xxx.jpg`（相对于 upfile 目录）
- **绝对路径**：如 `/usr/local/app/ai-brain/upfile/xxx.jpg`
- **base64**：如 `data:image/jpeg;base64,/9j/4AAQ...` 或纯 base64

**输出字段：**

- `sent`：是否全部成功（图片全成功 + 文本成功）
- `image_count`：收集到的图片总数
- `images_sent`：实际发送成功的图片数
- `text_sent`：文本是否发送成功
- `error`：错误信息汇总
- `image_warnings`：图片收集时的警告（如文件不存在）

## 请求回调（引用回复）

**配置：**

- **请求回调**：不等待（发完即走）/ 等待引用回复（挂起）
- **回调超时(秒)**：默认 1800 秒（30 分钟）；超时后带 `timeout=1` 继续下游
- 仅支持**单个接收者**；需要等待回复时不要用「全部账号」

**使用方式：**用户在微信里**长按机器人发出的那条消息 → 引用 → 输入回复**。平台通过被引用消息的 ID 精准匹配到对应的等待任务，恢复对应工作流。

**为什么必须用引用：**同一个微信里可能同时挂着多个审批/确认任务，引用回复能让每条消息精准找到自己的回调，互不干扰；普通消息（没有引用）会正常放行，不会被误吞。

**回调输出字段：**

- `reply_text`：用户回复内容
- `reply_from`：回复人 ID
- `reply_time`：回复时间
- `ref_message_id`：被引用的机器人消息 ID
- `timeout`：是否超时（布尔值）
- `text_message_id`：本次发出的消息 ID

等待记录保存在内存中（保留 24 小时），服务重启后清空，不写数据库。用户若引用了一条已过期/已处理的消息，会自动收到「该请求已过期」的提示，不会触发工作流。

上游来一个审批列表时，用「批量异步派发」把每张单派给同一个子项目（发微信 → 等待引用回复 → 调用审批），多个审批人可同时回复，全部处理完再汇总，避免一单未处理就阻塞后续。

## 常见问题

不会异常。如果图片路径留空且上游没有图片，`image_count=0`，只会发送文本（如果有文本）。

如果文本和图片都为空，会返回错误"消息内容与图片都为空"。

直接文件路径就可以，不需要转 base64。后端会自动读文件、校验图片头、加密上传。

微信触发器输出的 `file_path` 就是相对路径，直接引用 `{{inputs.触发器.file_path}}` 即可。

**选择账号**：从已绑定账号列表中选择，后端查库获取该账号绑定的用户ID进行发送。适合固定发送给某个/某些用户。

**引用变量**：变量值直接作为接收者用户ID（如 `{{微信消息触发.from_user_id}}`），不查库。适合"谁发的消息就回复给谁"的场景。

# 小米集成

## 启用配置

在「管理后台 → 服务配置 → 小米集成」中配置：

- **账号密码**：小米账号和密码
- **PassToken**：可选，用于云端API认证
- **云端MQTT**：启用后通过云端MQTT实时接收设备事件
- **本地中枢**：启用后通过本地中枢执行设备控制（延迟更低）

## 节点说明

| 节点 | 用途 |
| --- | --- |
| 小米事件 | 监听设备状态变化，作为触发器 |
| 小米查询 | 查询设备当前状态 |
| 小米控制 | 控制设备（设置属性/调用动作） |
| 运行数据集 | 批量获取多台设备状态，按房间分组，输出 JSON/文本 |
| AI-小米控制 | 自然语言控制小米设备（需先授权设备和属性） |

## 执行通道

小米控制节点支持两种执行通道：

- **本地中枢**：通过本地小米中枢执行，延迟低，需要本地中枢在线
- **云端**：通过小米云端API执行，兼容性好，部分新设备仅支持云端

系统会根据设备类型自动推荐通道。新款小爱音箱的TTS功能仅支持云端通道。

## 设备事件数据

小米事件节点触发时，输出数据包含：

- `data`：设备属性数据（如温度、开关状态）
- `before` / `after`：变化前后的值
- `prop`：变化的属性名
- `name`：设备名称

## 音箱对话触发

**配置项：**

- **音箱设备**：选择要监听的小爱音箱（从云端扫描获取，设备ID不会变）
- **回答来源**：云端 / 本地
  - **云端**：通过小米云端API轮询获取对话内容，适合所有音箱
  - **本地**：通过音箱本地接口接收对话推送，延迟更低，需要音箱支持本地接口

**输出数据：**

- `text`：用户说的话
- `name`：声纹识别的用户名（本地模式支持）
- `did`：音箱设备ID

1. 音箱列表在添加节点时刷新一次即可，设备ID不会变，不需要每次打开都刷新

2. 云端模式下，系统会自动轮询音箱对话，轮询失败或登录失败会写入系统日志

3. 本地模式下，音箱通过C程序监控本地语音日志，将对话内容推送到平台接口

4. 这个节点是独立的对话内容获取，与原有的小米设备控制逻辑完全无关

## 等待音箱回答

**配置项：**

- **音箱设备**：选择要等待回答的小爱音箱
- **超时时间**：等待用户回答的最长时间（秒），超时后按超时行为处理
- **超时行为**：超时后继续执行（使用默认输出）或终止工作流
- **默认输出**：超时时使用的默认回答文本
- **回答来源**：云端 / 本地（与音箱对话触发节点一致）

**执行逻辑：**

- 节点执行时，先通过小米控制节点或TTS让音箱播放问题
- 然后工作流**挂起等待**，不继续执行下游
- 当用户对音箱说话时，云端轮询器或本地接口检测到新对话
- 如果对话匹配当前等待的音箱，则**恢复工作流**，将用户回答作为输出继续执行
- 如果超时未收到回答，则按超时行为处理

**输出数据：**

- `text`：用户的回答内容
- `name`：声纹识别的用户名（本地模式）
- `timeout`：是否超时（布尔值）

1. 同一音箱同时只能有一个等待，后启动的会覆盖先启动的

2. 等待期间收到的对话会被这个节点消费，不会再触发音箱对话触发节点的工作流

3. 播放问题需要在这个节点之前用小米控制节点或TTS节点完成，这个节点本身不播放问题

## 运行数据集（小米）

**配置：**选择设备、每台设备要读取的属性、输出类型（JSON / 文本）。属于惰性数据源，被下游引用时才读取，适合作为 AI 生成节点的上下文。

## AI-小米控制

**授权机制（重要）：**

- 在节点配置里**逐个添加允许被控制的设备和属性**，只有授权表中的设备/属性才会被执行控制
- **查询状态不需要授权**；未授权的控制操作会返回"没有授权该属性"，不会执行
- 类似小米数据集的逐设备/逐属性添加方式，便于精确控制可操作范围

**配置：**

- **模型**：解析意图的 AI 模型，按所选模型自动适配结构化输出方式
- **提示词**：可自定义，系统会把授权设备与属性清单一并提供给模型
- **回复模式**：模板返回 / AI 生成回复
- **输入来源**：自动 / 引用上游变量 / 固定文本

**动作类型：**打开（turn_on）、关闭（turn_off）、设置（set）、查询（query）。识别不到设备时会做关键词兜底匹配，并返回疑似设备列表。

**输出：**一个 `text` 字段，把执行结果拼成通俗文字，可直接接微信/音箱播报。

# 门禁与监控

平台集成了海康威视门禁（ISUP / EHome 协议）与 GB28181 国标视频监控，需要在「管理后台 → 服务配置」中先启用对应集成。

## 海康门禁

设备通过 ISUP/EHome 主动注册到平台后，每次开门事件都会触发该节点。输出字段通常包含卡号、人员姓名、门编号、事件时间，可用于"开门 → 播报欢迎语 → 记录"等场景。

配置目标门点后，执行即下发一次远程开门指令。可由 AI 节点、微信指令或 HTTP 请求触发。

设备会持续推送心跳，平台只对真正的门禁事件（刷卡/人脸）做处理，心跳不写库，避免频繁的磁盘写入。

## GB28181 视频监控

摄像头作为国标设备注册到平台内置 SIP 服务器（默认 5060 端口），布防后上报告警即可触发工作流。

对指定国标设备下发布防（SetGuard）或撤防指令。设备注册后平台会自动维持布防状态。

# 常见问题

### Q：工作流保存后不自动执行？

工作流必须「启用」后才会自动触发。保存只是保存配置，不会自动运行。点击工作流页面顶部的「启用」按钮。

### Q：怎么引用上游节点的输出？

推荐使用节点配置中的「选择字段」按钮，点击后会列出所有上游节点的输出字段，选择后自动生成正确的变量路径。手动输入可以用 `{{data.字段名}}` 格式。

### Q：AI生成节点怎么传入图片？

将RTSP抓图或图片下载节点连接到AI生成节点的 `image_in` 端口。注意必须是多模态模型才能处理图片。

### Q：判断节点不通过怎么办？

检查以下几点：

- 字段路径是否正确，推荐用「选择字段」按钮重新选择
- 数据类型是否匹配（字符串/数字/布尔值）
- 比较值是否正确（注意大小写、空格）
- 查看节点执行日志，确认上游输出的实际值

### Q：延时节点会阻塞整个工作流吗？

不会。延时节点是非阻塞的，下游节点会在指定时间后执行，不会影响其他并行分支。

### Q：日志保留上限是怎么计算的？

日志保留上限是**按工作流分别计算**的，每个工作流最多保留N条执行日志（默认100条），超出后自动删除最早的日志。

不是所有工作流加起来总共保留N条，而是每个工作流各自保留N条。频繁执行的工作流不会挤掉其他工作流的日志。

可以在管理后台 → 日志页面修改「每工作流保留上限」。清空日志后会自动执行VACUUM释放磁盘空间。

### Q：数据实体节点的固定值不生效？

固定值功能仅在**写入模式**且**数值类型**下生效。如果节点是读取模式，固定值不会生效。

配置方法：操作类型选「写入」，数据类型选「数值」，运算符选「加/减/乘/除」，值来源选「固定值」，输入常量值（如1）。

### Q：禁用工作流后正在执行的会停止吗？

不会。禁用会停止新的触发（定时、事件、循环），但正在执行的工作流会继续跑完。

### Q：小米设备控制没反应？

检查以下几点：

- 设备是否在线
- 执行通道是否正确（部分新设备仅支持云端）
- 参数是否正确（如TTS的文本参数）
- 查看节点执行日志，确认返回结果

### Q：HA事件节点不触发？

检查以下几点：

- HA集成是否启用且连接正常（服务配置页面看事件连接状态）
- 实体ID是否正确
- 从状态/到状态的过滤条件是否太严格（可以先留空测试）
- 工作流是否已启用

### Q：区间判断（在区间内）为什么不生效？

检查以下几点：

- **取数字段路径是否设置**：如果上游是设备对象（如空调），必须设置字段路径提取数值字段（如 `Temperature`），不能留空比较整个对象
- **数据类型是否为数值型**：区间判断仅在数值型下可用，字符串/布尔型没有区间运算符
- **配置是否已保存**：修改节点配置后需要保存工作流，区间配置才会持久化到数据库
- 查看节点执行日志的 `input_value` 字段，确认实际比较的值是否为数字

### Q：小米音箱播放文本被下游指令打断？

小米控制节点发送指令后默认立即触发下游，下游的播放指令会打断当前播放。解决方法：

- 在播放文本的小米控制节点开启「执行后等待」
- 选择「按文本长度自动估算」，系统会根据播放文本长度计算等待时间
- 可调整「每字秒数」适配不同音箱的语速（默认0.3秒/字）
- 也可以选择「固定时长」手动设置等待秒数

### Q：AI生成节点没有图片时也执行了？

AI生成节点的 text_in 端口如果连了知识注入、读取记忆、数据实体等惰性数据源，这些节点会自动执行并提供文本，导致AI节点即使没有图片也会执行。

解决方法：在AI生成节点开启「必须有图像输入才执行」，无图时节点会跳过，不触发下游（如邮件、播报）。

### Q：判断走了「不满足」，但「满足」分支的下游节点还是执行了？

这通常是因为该下游节点还连了其他非分支数据源（如知识注入、数据实体等惰性节点）。但根据分支阻断规则，只要有分支边不匹配，节点就会被阻断，惰性数据源不会解除阻断。

如果确实发生了这种情况，检查：

- 该节点是否真的连了判断节点的分支端口（matched/unmatched）
- 连线的源端口是否正确（不是普通的 out 端口）
- 查看执行日志，确认节点的实际执行状态和输入数据

### Q：循环/延时节点修改配置后不生效？

循环和延时节点的调度是在工作流启用时注册的，修改配置后需要**禁用再启用**工作流才能生效。普通节点（如判断、数据实体）修改后保存即生效。

保存工作流时，如果项目中有循环或延时节点，系统会提示需要停止重新启用才生效。可以勾选「本次会话不再提示」关闭该提示。

### Q：登录状态会过期吗？

会。登录会话有效期为**7天**，过期后需要重新登录。容器重启或更新镜像（data目录挂载的情况下）不会导致登录失效，因为session签名密钥保存在 `data/secret_key.txt` 中。

如果是全新安装或重装容器（不挂载data目录），会生成新的密钥，旧的登录态自动失效，需要重新登录。

### Q：备份包含哪些内容？

备份包含所有配置数据（工作流、模型、知识库、用户、设置等），以及session签名密钥（secret_key.txt）。恢复备份后，登录态保持有效，无需重新登录。

备份文件使用AES加密，需要妥善保管备份密钥。日志数据库（执行历史）不包含在备份中。

# API手册

平台提供HTTP API，供外部系统（如HomeAssistant、Node-RED、脚本等）调用。

大部分API需要登录认证（Session Cookie）。以下列出的是无需登录、可直接调用的公开API。

需要认证的API请在登录状态下从浏览器开发者工具查看具体调用方式。

### 触发工作流（Webhook）

如果工作流中有Webhook触发器，可以通过HTTP请求触发工作流执行。

**接口地址：**

```
POST /api/<Webhook名称>
```

#### 不认证模式

无需携带认证信息，直接调用即可（如果配置了IP白名单，需在允许的IP范围内）。

```
curl -X POST "http://平台地址/api/我的webhook" \
  -H "Content-Type: application/json" \
  -d '{"text": "测试"}'
```

#### 应用认证 - Key模式

在请求头中携带API Key，支持以下几种方式：

- `Authorization: Bearer <api_key>`
- `X-Webhook-Key: <api_key>`
- `X-API-Key: <api_key>`
- URL参数：`?key=<api_key>`

```
curl -X POST "http://平台地址/api/我的webhook" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer whk_xxxxxxxx" \
  -d '{"text": "测试"}'
```

#### 应用认证 - 用户模式

先调用登录接口获取Token，再在请求头中携带Token。

**登录接口：**

```
POST /api/webhook-auth/login
Content-Type: application/json

{"username": "应用用户名", "password": "应用密码"}
```

返回：

```
{
  "code": 0,
  "data": {
    "token": "wht_xxxxxxxx",
    "expires_at": "2026-09-09 20:00:00",
    "expires_in": 7200,
    "app_name": "我的应用"
  }
}
```

**携带Token调用：**

```
curl -X POST "http://平台地址/api/我的webhook" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer wht_xxxxxxxx" \
  -d '{"text": "测试"}'
```

支持单个IP（如 `192.168.1.100`）和CIDR网段（如 `192.168.1.0/24`）。Webhook启用独立白名单时覆盖应用级白名单。

# MCP 接入

MCP（Model Context Protocol）是让外部 AI 智能体标准化接入云麓AI 的通道。接入后，受信任的智能体可以帮你**建 / 改工作流、写 / 运行脚本、读取节点目录与运行记录、直接触发节点执行**——相当于把平台能力开放给 AI 助手使用。

## 它是怎么工作的

- **一条通道，两个实例**：主站复用 `8765` 端口、在同一进程内运行两个 MCP 实例——`/mcp` 对接笔记组（MuseNote），`/musemcp` 对接主站（云麓AI brain 组）；工具可见性按端点划分。
- **认证 = 接入密钥**：每个密钥是一串 `bt_` 前缀的令牌，智能体在请求头带上即可调用，无需账号密码。
- **服务端不保存主站凭据**：MCP 服务端只校验令牌有效性，不存储你的平台账号密码。

## 开通过程

1. 进入 **管理后台 → AI 接入** 页（仅管理员可见）。
2. 在「密钥」卡片区点击**新建密钥**，为这个智能体起个名字（如「我的助手」），系统生成一条令牌。
3. **明文令牌只在创建时显示一次**，请立即复制保存；之后页面只显示指纹与调用次数。重签会使旧令牌立即失效。
4. 把端点地址与令牌填进你的 MCP 客户端即可连上（端点见下方说明）。

实际可用的域名 / IP、端口与端点路径，请在「AI 接入」页的说明区查看，以页面实时显示为准。

## 控制智能体能做什么（节点开放给 AI）

- 「AI 接入」页的**「节点开放给 AI」**总表，按分类列出**全部节点**，每个节点一个开关。
- 勾选 = 该节点对 MCP 智能体**可见且可用**；未勾选 = 对 AI **不可见、不可用**。
- 默认开放 41 个节点：原基础节点（逻辑控制 / 数据处理 / AI 能力 / 触发器 / 记忆·知识 / 脚本）＋ 微信发送、笔记查询 / 执行、知识库写入、项目类 5 个、发邮件、HTTP 请求、下载保存图片、目录同步、图片读取等。新建节点默认关闭，需手动勾选。
- 改动**即时生效**，无需重启。

微信发送、发邮件、HTTP 请求、笔记执行等会真实对外动作的节点，除在表里开放外，还需对应外部服务（微信绑定 / SMTP / 网络出口 / MuseNote 已绑定主站）在线才能真正执行。关闭某节点只是让 AI 看不到它，**不影响你本人在画布里手动使用**。

## 活动日志与审计

- 「AI 接入」页的**「AI 活动日志」**记录每个密钥真正调用了什么（读工作流、建脚本、触发运行等），便于审计。
- 每个密钥有**调用次数**统计，可在密钥卡片区查看活跃度。

## v19（2026-09-20）

### 历史执行回放

- 工具栏运行按钮旁新增时钟图标，点击可选择最近20次执行记录
- 选择某次执行后，画布顶部出现控制条，支持左右箭头切换上一次/下一次
- 控制条显示当前执行序号、时间、成功/失败状态
- 点击关闭按钮退出回放，回到最新执行状态
- 回放模式下，节点历史日志面板只显示当前选中那次执行的日志

### 连线颜色优化

- 本次执行的连线为**实线**：成功绿色，失败红色；该分支确实没走为灰色虚线
- 本次进入但还没有结果的节点（等待/执行中）为琥珀色短虚线
- 本次没执行、但**历史上执行过**的连线为长虚线，颜色取自该节点上一次执行结果
- 从来没有执行过的连线为灰色细实线
- 鼠标悬停连线可查看提示，明确区分「本次执行 / 历史执行（含时间）/ 从未执行」

### 运行体验优化

- 运行工作流后自动刷新执行状态，连线颜色实时更新
- 画布每 4 秒做一次轻量检查：外部触发（微信消息、定时、Webhook、MQTT、Home Assistant、小米事件等）产生的执行也会自动更新连线颜色，无需手动刷新页面
- 页面切到后台（或不在画布页面）时自动暂停检查，不占用资源
- RTSP抓图节点配置弹窗点击确定后自动保存到数据库

### RTSP抓图增强

- 支持从上游节点获取摄像头名称，自动匹配对应的RTSP地址

- 摄像头名称需在后台设备管理中保持唯一
- 节点输出新增 camera_debug 字段，包含解析到的名称、匹配结果、可用名称列表，便于排查

### 定时触发器随机时间

- 固定时间类型下新增「随机时间」模式
- 设置时间范围（如 08:00 ~ 10:00），系统每天在该范围内随机选一个时间执行
- 每次执行后重新随机下一次的时间
- 间隔类型也支持随机间隔：使用 {{random(min,max)}} 表达式
